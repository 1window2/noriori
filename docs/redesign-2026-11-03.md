# noriori 재설계안 (2026-11-03)

남은 P0·P1을 전수 검토한 결과로 다시 짠 구현 계획입니다. 근거는 [open-items](audit/open-items-2026-11-03.md)(추적표 미완 540행, 문서 어긋남 51행 배정)입니다. 작업량은 측정값으로만 적습니다.

## 1. 무엇이 드러났나

| 발견 | 뜻 |
|---|---|
| 추적표가 낡음. 올릴 행 47, 낮출 행 20, 폐기할 행 6 | 진행률 숫자를 믿을 수 없음. 먼저 고침 |
| 지선 역에서 본선 역으로 가는 기록을 입력할 수 없음 | `경로 자동 전개`가 절반만 됨 |
| 폐역 묶음 1,501곳 중 1,492곳이 `approx` 좌표 | §4.7 규칙대로면 지도의 폐역 점이 거의 사라짐. 규칙이 현실과 어긋남 |
| 지도 물, 도도부현 경계, 역 이름 글리프가 온라인 배경에만 있음 | 오프라인이면 지도가 비는데 P0 요구 |
| 여정, 다구간, 사진, 배지, 공유 카드, 그래프, 캘린더는 명세가 이름 수준이고 승인 시안이 없음 | 바로 만들면 임의 UI가 됨. 시안이 먼저 |
| 영업km 표에 오류 16구간 | 위키백과와 실제 선로로 고침 (판 2026-11-02.7) |

## 2. 원칙

1. 구현 전에 명세 본문과 시안을 끝까지 읽는다. 없으면 시안부터 만들어 승인받는다.
2. 단순화는 먼저 묻는다. 묻지 않은 단순화는 `부분`이다.
3. 시험은 실제 경로를 지난다. 저장을 건너뛴 시험은 저장을 증명하지 않는다.
4. 진행 보고는 추적표 숫자로 한다. 화면 항목은 실기기와 목업을 나란히 본 뒤 올린다.
5. 판 번호는 내용이 바뀔 때마다 올리고 재생성은 `tools/all.sh` 한 곳으로 한다.

| 1 | 끝남. 분기 `side` 97행 채움 (28행은 각도로 판단 불가). `지도 미표시` 오탐 고침. 현행 `approx`는 4곳이 남았고 지도에서는 선 위로 옮겨짐 | 검사 통과, 판 올림 |

## 4. 결정

### 4.1 권장안대로 진행 (다르게 원하면 말씀해 주세요)

| 항목 | 정한 것 |
|---|---|
| 지선→본선 입력 | P0로 봄 |
| 역 위치 규칙 | 폐역은 `approx`도 점을 유지하고 좌표 없는 것만 뺌. 현행 13곳은 좌표 보정 |
| 운전 계통 저장 | 승차권을 씀 |

| 원어 병기 | 역 선택기는 항상, 지도 이름만 옵션, 로마자 3단은 뺌 |
| 파랑 글자 예외 | 되돌리기와 출발·도착 |

|---|---|---|
| 5 | 빌드 때 N03을 도도부현 단위로 합치고 간략화해 `base.pmtiles`(육지, 도도부현 경계)를 만듭니다. 앱에 넣고 `manifest`에 올립니다. 온라인 배경은 그 위에 덧그립니다. 라틴 글자는 PBF 글리프를 앱에 넣고, 한글과 한자, 가나는 기기 글꼴을 씁니다. 비행기 모드에서 지도가 뜨면 끝이고, 칠하기 시간은 실기기에서 잽니다 | N03 원본 632MB 내려받기 승인 |

## 4.6 공개 전 검토 (2026-11-03)

결함과 남은 판단은 [release-review-2026-11-03.md](release-review-2026-11-03.md)에 있습니다. 방문 역 도도부현별 통계는 사용자 지시로 시안 없이 넣었습니다. 통계 입구 줄의 `방문 역`에서 들어갑니다.

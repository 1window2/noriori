## 2. 1950 기준일·열람 전용 축소의 후속 반영 (높음~중간)

- 상태 서술: DESIGN 85(✅), 1621("전 범위 구축됨"). 실제로 1950~1969 폐선은 아직 DB에 없음.
- 등급 정의: §4.1 표(742·745·822)에 기준일·교차 검증 조건이 없음. 894줄 "기준일에 걸치면"은 1969 기준의 잔재(1950-01-01에는 연·연대 값이 걸칠 수 없음). 943·958줄 폐지일 NULL 처리가 서로 다름.
- 목록: 760·764·1705줄이 "완전한 목록은 위키 일람으로(Phase 3)", "1970~1985 대조 상대 없음"으로 남음. N05가 1950년 이후의 닫힌 목록.
- 연도: 705·1075·982줄에 "연도별 완주율·타임 슬라이더·연도별 그래프는 1950부터"가 없음.
- 로드맵·남은 결정: §16에 N05 재구축, 사철 분모 편입, 열람 전용 범위 재결정, 노면전차 단계가 없음. §17에 남은 결정 표가 없음(머리말은 "남은 결정은 §17"). ARCHITECTURE §4.3·§8에도 단계 없음.
- 분모: 531·1629·1633·1651줄에서 `outside`가 언제 `normal`로 가는지, 1950~1969 국철 폐선을 어떻게 둘지 정해져 있지 않음 → 결정 질문 1.

## 3. 지도·선형 정의 (높음)

- `edge.geometry_quality`가 OSM 805구간을 `none`으로 적음. 지도에는 그려지고, `route.map_coverage`(none 57, partial 58)와 §4.7의 "none = 없음"이 실제와 맞지 않음. N05 311구간은 `precise`인데 N05 조건상 오차가 수백 m.
- §2.11·§7.2 1073줄: 2005년 이전 폐선은 OSM만으로 그린다고 적었지만 N05가 `rail.pmtiles`에 들어감.
- 909줄: `approx` 좌표는 점을 찍지 않는다고 했지만 결정(역 점은 같은 규칙으로 선 위)과 코드는 선 위에 찍음.
- 1551줄 짝 맞춤에 `rail-osm.pmtiles`가 빠짐(같은 판의 edge 번호를 씀).
- 선형 우선순위(N02 최신판 → 옛 판 → OSM → N05, 끝이 역에서 300m 넘으면 N05)가 어디에도 없음.

## 결정 질문 (사용자)

1. **폐선 분모 편입.** 1950~1999 폐선(국철·사철)은 N05와 목록 대조가 끝날 때까지 `outside`로 두고, 끝나면 한 번에 `normal`로 옮겨 역대·특정 연도 분모에 넣는다. (추천)
2. **환승 번호.** ①=지나감, ②=위(기점 쪽)에서 와서 끝남, ③=아래에서 와서 끝남으로 종류에 번호를 고정하고, 없는 종류의 번호는 건너뛴다. (추천)
3. **역 이전 노드.** 같은 선로 위에서 옮긴 경우(지하화·고가화·몇백 m 이동)는 노드 하나에 `move`, 선로가 갈라져 다른 자리로 옮긴 경우는 옛·새 노드를 두고 `moved.json`. (추천)
4. **내부 ID 예외.** edge(`e_`), 승계 사슬(`lg`), carryover(`c`)는 사용자 기록에 저장하지 않는 내부 ID라 번호를 허용한다. 공개·기록에 쓰는 ID(n, l, r, s, o, g, hub, a)만 영어 이름. (추천)
5. **기록 탭 목록.** `outside`·`extra` 구간도 목록에 나와 기록할 수 있게 하고, 완주율 합계에서만 뺀다. (추천)
6. **날짜 자동 모름.** 고른 구간이 그날 탈 수 없으면(폐지 뒤·개업 전·운휴) 선택은 유지하고 날짜를 날짜 모름으로 바꾼다. (추천)
7. **N05 선형의 타일.** `rail.pmtiles`에 함께 두고 출처는 `data/source/geometry/n05.yaml`로 구분한다(문제가 생기면 그 파일을 빼고 다시 빌드). 별도 타일 파일로 나누지 않는다. (추천)

## 질문 없이 결정 목록·사실대로 고칠 것

- 위 1~8절의 나머지 전부. 기준은 결정 목록과 저장소 실제입니다.
- `geometry_quality`는 선 유무(`precise`/`none`)로 두고 출처는 새 열 `geometry_source`(n02/n05/osm)로 나눔. `map_coverage`는 출처와 무관하게 선 유무로 계산.
- 판 릴리스 검사(appsim, invariants, 재해석 비교)는 `dataset` 워크플로 대신 로컬 절차로 적음. 판 번호 검사는 로컬.
- 노리츠부시 표는 시드 생성 원천이자 대조 기준(2026-11-02 결정). 사이트 내부 ID는 쓰지 않음.
- 이름 `source`는 근거를 적음. 나무위키 제목이 있으면 `namuwiki`(규칙과 같아도).
- 지문 실패 기준: 좌표 1km 이상 이동, 이름 완전 변경, redirect 순환.
- manifest의 최소 앱 버전과 서명은 명세에 남기고 미구현으로 표시.

## 동결 방법 (안)

- 고친 뒤 DESIGN·ARCHITECTURE 머리말 상태를 `동결 (날짜)`로 바꿉니다.
- 동결 뒤에는 사용자 결정이 있을 때만 명세를 고칩니다. 고칠 때는 명세를 먼저 바꾸고 변경 기록을 남긴 뒤 다시 동결합니다.
- 구현과 데이터는 동결된 명세와 `docs/spec-trace/`를 기준으로 맞춥니다. 명세와 다르게 만들어야 하면 먼저 묻습니다.
- 커밋할 때 `spec-v1` 같은 태그를 붙여 동결 시점을 고정합니다.

## 1. 기존 서비스의 DB 방식과 채택안

| | 노리츠부시 온라인 | 鉄ログ |
|---|---|---|
| 방식 | **규칙 기반 논리 DB** (사람이 관리) | **GIS 선형 우선** |
| 출처 | 『鉄道要覧』(영업km), JTB 시각표, 『停車場変遷大事典』 | 국토수치정보, OpenStreetMap |
| 노선 단위 | 공식 선로 명칭. 신칸센·재래선 별개. 중복 계산 금지 | 공식 선로 명칭 |
| 폐선 | JR·국철 약 1970년 이후 + 사이트 개설 후 폐선 전부 | 미지원 |
| 이설 | 신선 + 옛 선로는 폐선 | 언급 없음 |
| 사업자 전환 | JR→사철: JR선 폐선 + 신규 노선 (기록 승계 안 함). 사철→사철: 승계 | 언급 없음 |
| 약점 | 사람이 관리, 지도 표현 약함 | 선형 끊김·이음매·역 순서 오류가 반복적으로 기록에 번짐 |

**채택**: 노리츠부시식 논리 DB를 기록의 기준으로, 鉄ログ식 지도 선형은 독립된 층으로. 두 층은 **ID로만 참조**하고 서로의 내용을 바꾸지 않는다.

### 1.1 노리츠부시 내부 구조 (2026-10-30, 로그인 세션에서 확인)
| 항목 | 확인 내용 | noriori 반영 |
|---|---|---|
| **노선 단위** | "노선 = 공식 노선 + 부분 번호". ID 형식 예: `24701` 函館本線, `24702` 函館本線 (砂原回り), `25302` 千歳線 (空港支線), `26701`·`26703` 根室本線 (滝川～富良野)·(新得～根室) — 중간 폐지로 끊긴 노선은 부분으로 나뉨 | 노선 아래 **계통(route)** 모듈 (§2.7) |
| **기록 방식** | 역 선택 라디오 버튼의 값이 **영업km**(函館 0.0, 五稜郭 3.4 …). 기록 = (노선 부분, 시작 km, 끝 km, 날짜) — 선형 참조(linear referencing) 방식 | 우리는 노드 ID 기반이지만, km 축은 계통별로 같은 방식으로 둠 |
| **날짜** | "날짜를 등록하지 않음" 선택지 있음 → CSV에 `0000-00-00` | 날짜 미상·부분 날짜 허용 (§5.4) |
| **폐역 표시** | 역 선택 목록에 `*東山`처럼 별표로 표시하되 **선택 가능, 폐지일 표시 없음**. 별표 = 폐역(신호장으로 바뀐 곳 포함)으로 판단: 宗谷本線의 2021년 폐역 12곳, 石勝線의 신호장이 된 楓·東追分·滝ノ上·十三里가 모두 별표 | 회색·선택 불가 + `~연도` (탑승일 기준으로 판단) |
| **운전 계통 검색** | "路線名で検索"에서 `中央快速線 東京～高尾`처럼 통칭으로 입력 → 저장 시 東北本線·中央本線·山手線 구간으로 분해. 화면에 "運転区間の詳細"(노선별 구간·km) 표시 | services 모듈 (§2.7) |
| **중복 구간** | JR은 한 구간을 한 노선에만 집계 (예외 4곳). 사철은 여러 사업자가 같은 구간에서 영업하면 사업자별로 따로 집계 | 집계 멤버십 규칙 (§2.7) |
| **개업 이력** | 노선마다 "구간·영업km·개업일" 표 보유 (예: 南小樽～札幌 32.2km 1880-11-28) | events 모듈의 `open` 이벤트로 동일 정보 |
| **폐선 (타임머신)** | 폐선은 별도 메뉴 "乗りつぶしタイムマシン". 국철·JR **139개 항목, 5,230.1km**. 사철 **28개 사업자, 약 506km** — 2000년대 이후 폐지가 중심 (가장 오래된 것은 1986년 菊池線) | §4.3 |
| **사업자 전환** | 北陸本線 敦賀～直江津, 東北本線 盛岡～青森, 二俣線 등 3섹 전환 구간이 타임머신(폐선)에 들어 있음 → JR→사철은 승계 안 함. 사철→사철은 안내문상 승계 | 우리는 기본 승계 + 옵션 |
| **부분 폐선 묶음** | 札沼線 北海道医療大学～石狩沼田 (1972년·2020년 두 번의 폐지를 한 항목으로 묶음) | 우리는 폐지 단계별로 구분 (§8) |
| **BRT 전환** | 日田彦山線 添田～夜明: 법적 폐지 전이지만 "열차로 탈 수 없게 되었으므로 폐선과 같이 취급" | 같은 규칙 채택 (`close` + `reason: brt`) |
| **사업자 분류** | JR각사 / 대형사철 / 준대형사철 / 공영 / 일반사철 / 모노레일 … | §2.5 분류에 채택 |
| **CSV 위치** | "登録した記録を編集する(乗車記録の参照・編集)" 화면 하단에 4개 링크 (JR+사철 / 전체, 각각 일반·코멘트판) | §10 |
| **지도** | 서버가 그린 SVG 이미지 한 장 (`map_svg.php`). 범위·사철 포함·선 색과 굵기·**기준일** 설정 가능 | 기준일은 타임 슬라이더와 같은 발상. 우리는 네이티브 벡터 지도로 즉시 반영 |

### 1.2 DB 구조 비교
| 항목 | 노리츠부시 온라인 | 鉄ログ | noriori |
|---|---|---|---|
| 기록의 기준 | (노선 부분, 시작 km, 끝 km) | **역별 방문 기록** + 역 사이 추측 (기본값). 구간 입력은 여러 역을 한 번에 표시 | (노선, 역, 날짜) → 구간으로 펼침 |
| 진행률 기준 | 영업km | **역 수** (표시 km는 선형 길이) | 영업km |
| 기록 수정 | 날짜·코멘트만, 구간은 지우고 재입력 | 역마다 수정, 일괄 삭제 없음 | 구간·역을 그 자리에서 전환, 일괄 삭제 ✅ |
| 역 신설 시 | km 기록이라 영향 없음 ✅ | 설명 없음 | 영향 없음 ✅ (기록은 노드 기준, edge 분할은 재계산으로 끝남) |
| 영업km 개정 시 | 기록이 km이므로 어긋날 위험 있음 ⚠️ (처리 방식은 미확인) | 설명 없음 | 영향 없음 ✅ (기록은 노드 기준) |
| 사업자 전환 | JR→사철은 폐선 + 신규 노선, 사철→사철은 승계 | 설명 없음 | 기본 승계, 끌 수 있음 ✅ |
| 시대 표현 | 노선별 개업 이력 표, 지도 기준일 | 없음 | 모든 구간·역에 기간 + 3가지 완주율 ✅ |
| 폐선 범위 | JR 139항목 + 2000년대 중심 사철 | 없음 | 1969-12-08 이후 국철·JR + 검증된 사철 (§4.6) ✅ |
| 부분 폐선 | 별도 항목으로 분리, 현행과 입력 화면이 나뉨 | 없음 | 한 노선 안에서 단계별로 표시 ✅ |
| 지선·중복 구간 | 노선을 부분으로 쪼갬 + 별칭 | 공식 명칭 기준 | 계통 + 집계 멤버십 + 운전 계통 (규칙은 노리츠부시와 동일) |
| 날짜 불확실성 | 날짜 있음 / 없음 두 가지 | 없음 | 일·월·연도·연대·모름 + 범위 계산 ✅ |
| 선형 오류의 영향 | 기록과 분리된 것으로 보임 | 기록에 번짐 ⚠️ | 기록과 완전 분리 ✅ |
| 데이터 관리 | 비공개, 운영자 1인 | 비공개 | 공개 파일 + PR + 자동 검증 ✅ |
| 역 방문 단독 기록 | 없음 | 역 탭 = **탑승 기록**이라 방문과 구분 안 됨. 역 두 개를 찍으면 사이가 칠해짐 (설정으로 끌 수 있음) | 구간과 분리된 별도 기록 ✅ |
| 운전 계통 입력 | 있음 (별칭 검색) | **없음** (공식 명칭만) | 있음 ✅ |
| 분기선 표시 | 없음 | 없음 | 입력 화면에 표시 ✅ (§8.1) |

**우리가 불리한 점도 있습니다.**
- 노리츠부시의 km 구간 기록은 구조가 매우 단순합니다. 우리는 이벤트 컴파일러, 경로 해석, 구간 분할, 승계 2모드 분모 계산이 필요해 **구현량이 훨씬 많습니다**.
- 노리츠부시는 오랜 기간 사람이 다듬은 데이터가 있습니다. 구조가 앞서도 **데이터 품질은 처음에는 뒤처집니다**.
- 역 방문만 따로 기록하는 앱은 있습니다. **駅ログ**(ekilog.app, iOS·Android, 11,000개 이상 역, 리뷰 기능)와 예전의 降りつぶし 계열이 그렇습니다. 다만 이들은 역 단위 앱이고, **구간 완주와 역 방문을 한 앱에서 분리해 함께 다루는 곳은 찾지 못했습니다.**
- 鉄ログ는 iOS 전용이고 Android판을 찾지 못했습니다. 직접 조작한 결과는 §1.3에 있습니다.
- 위 표에서 노리츠부시·鉄ログ의 내부 구현은 화면과 공개 설명으로 추정한 것이며, 소스를 본 것은 아닙니다.

## 2. 마스터 DB 모듈 설계

### 2.1 모듈 구성
```
data/source/       사람이 소유하는 원본 (§2.10)
├─ nodes/          역 · 신호장 · 분기점 · 화물역 · 경계 노드 (ID, 종류, 소속 group) — §2.8 B
├─ groups/         같은 역으로 치는 노드 묶음 — §2.8 B
├─ redirects/      데이터 정정으로 합치거나 바꾼 ID — §2.10
├─ operators/      사업자 (분류는 §2.5)
├─ lines/          노선 정체성 (공식 명칭, 종류, 기본 분모 등급)
├─ routes/         노선 안의 계통 (본선 · 지선 · 끊긴 부분) — §2.7
├─ services/       운전 계통·통칭 (中央快速線 등) — 입력 편의용, 통계 단위 아님 — §2.7
├─ edges/          인접 노드 사이의 물리 선로 (ID, 양 끝 노드, seed_line, route_only)
├─ events/         ★ 선로·정차·귀속·이름의 변화 이력
├─ hubs/           ★ 걸어서 갈아탈 수 있는 역 묶음 (이름이 달라도 됨) — §2.9
├─ junctions/      ★ 선로가 실제로 갈라지거나 이어지는 곳과 방향 — §2.9
├─ lineage/        ★ 승계 사슬의 표시용 정보. 사슬 자체는 transfer에서 컴파일 — §2.9
├─ archive/        ★ 열람 전용 역·노선. 순서와 연도만 있어도 됨, 선로망과 분리 — §4.5
├─ km/             구간(edge)별 영업km — 거리의 유일한 출처
├─ positions/      노드 좌표 (출처·정밀도 포함)
├─ geometry/       edge별 선형 (출처별 하위 폴더)
├─ names/          ja / ko / en 표기, 별칭, 출처 — §9
├─ staging/        검증 전이거나 순서가 불명한 항목. 앱에 들어가지 않음
└─ checks/         CI 예외 목록 (intentional_gap 등) — §2.6
```

원본 파일은 사실별로 나뉘어 있지만, **파생 단계에서는 서로 만납니다.** 어떤 변경이 어디까지 번지는지 아래 표로 관리합니다.

| 모듈 | 참조 대상 | 직접 바뀌는 것 | 파생까지 번지는 곳 |
|---|---|---|---|
| nodes, operators, lines, edges | 없음 (뼈대). edge의 `seed_line`만 line ID | — | 거의 전부. 추가·분할은 §2.10의 도구로 |
| routes | line·node ID | 계통 구분, 역 선택 화면 | `route_edge`, `route_stop`, `route_link` |
| **events** | 뼈대 ID | 존재 기간, 귀속, 상태 | `edge_attr`, `route_*`, `denominator` |
| km | edge ID | 거리 | `denominator`, `closed_section` |
| positions | node ID | 지도 | 끝나는 노선의 방향(좌표 근거), 300m 환승 후보 |
| geometry | edge ID | 지도 | `geometry_quality`, `map_coverage`, 도도부현 경계 km |
| names | 모든 ID | 표시 문자열, 검색 색인 | 없음. **파이프라인의 조인 키로 이름을 쓰지 않음** |
| hubs, junctions | node·line·edge ID | 입력 화면의 환승·분기 표시 | `route_link`. junction이 바뀌면 환승 줄도 바뀜 |
| lineage | line ID | 이름 병기 | 없음 |
| archive | node·line ID (자리 표시만) | **노선 화면의 열람 표시만**. 기록·통계·지도에 영향 없음 | 없음 |

- **선로·정차·귀속·이름의 시간은 `events/`에만 둡니다.** hub, junction, 좌표, 운전 계통처럼 그 사실 자체의 유효 기간은 해당 파일에 둡니다.
- 뼈대에는 날짜가 없습니다. 작은 변화는 이벤트 한 줄로 끝나지만, 신선 개업과 병행 재래선 이관이 겹치는 큰 변화는 여러 모듈을 함께 고칩니다. 변경 유형별 도구와 체크리스트로 처리합니다 (§2.10).
- 선형이 틀리거나 없어도 events·km만으로 기록·통계가 완전히 계산됩니다.

### 2.2 이벤트 종류
**핵심 원칙: 선로 구간(edge)은 "지금까지 존재한 모든 노드로 가장 잘게 나눈 단위"로 쪼개 둡니다.** 과거의 역이 생기고 없어진 일은 선로를 닫았다 다시 여는 것이 아니라 `open_stop`·`close_stop`으로 적습니다. 그래서 과거의 역 변화는 구간 수나 총거리를 바꾸지 않습니다. **앞으로 생길 신역은 미리 쪼갤 수 없으므로** 그때 `split-edge` 도구로 나눕니다 (§2.10).

| 이벤트 | 대상 | 의미 | 대표 사례 |
|---|---|---|---|
| `open` / `close` | edge | 선로 구간의 영업 개시·종료. **`open`은 `operator`·`line`이 필수**이고 집계 멤버십이 여기서 만들어짐. 선택 필드 `class`는 분모 등급. **`close`도 `line` 필수** (`last_service`, `legal_abolition` 별도 기록) | 신선·연장 개업, 부분·전선 폐선 |
| `suspend` / `resume` | edge | 휴지·불통, 재개 | 재해 불통 |
| `open_stop` / `close_stop` | (계통, 노드) | 그 계통의 **정차역**이 되거나 그만둠 | 신역 개업, 폐역 |
| `transfer` | edge 묶음 | 귀속 변경. **선로는 닫히지 않음.** `from`·`to`가 모두 있으면 이관, `to`만 있으면 사업자 추가, `from`만 있으면 사업자 철수 | JR → 3섹 전환, 게이세이의 호쿠소선 구간 참여, 산요의 고베고속선 철수 |
| `relocate` | edge 묶음 | 옛 구간 `close` + 새 구간 `open`을 한 번에, 서로 연결. 새 구간은 옛 구간의 노선·사업자를 이어받음 | 댐 건설에 따른 이설 |
| `rename` | node·line·operator | 명칭 변경 | 역명 변경, 사명 변경 |
| `move` | node | 같은 역이 위치만 옮김 (좌표에 날짜를 붙임) | 역 이전, 지하화 |
| `km_change` | edge | 그 구간의 영업km 변경 | km 개정 |
| `set_class` | edge 묶음 | 분모 등급 변경 (`line` 필수) | 정기 열차가 없어진 구간 |

**`a..b`를 푸는 규칙**: edge는 처음 놓인 노선을 불변 사실 `seed_line`으로 가집니다. 귀속이 바뀌어도 이 값은 그대로입니다. 그래서 귀속과 경로가 서로를 기다리지 않습니다.

| 이벤트 | `a..b`를 찾는 범위 |
|---|---|
| `open` | `seed_line`이 그 `line`인 edge |
| `close`, `set_class` | `line`의 전날 멤버십 |
| `transfer` | `from.line`의 전날 멤버십 |
| `to`만 있는 `transfer` | `within`에 적은 노선의 전날 멤버십 |

같은 날의 이벤트는 모두 전날 기준으로 풉니다.

**규범 규칙 (기여자마다 다르게 입력하지 않도록)**
| 상황 | 규칙 |
|---|---|
| 기간 표기 | 모든 기간은 `[from, to)`. `valid_to`는 더는 탈 수 없게 된 첫날, 곧 마지막 여객 운행일 다음 날. 날짜 판정은 JST |
| 마지막 운행일 ≠ 법적 폐지일 (삿쇼선: 2020-04-17 운행 종료, 05-07 폐지) | 역 선택기·완주 판정은 **마지막 운행일** 기준. 법적 폐지일은 수록·기록 범위 판정(§4.6)에 씀 |
| BRT 전환 (気仙沼線, 日田彦山線) | **BRT 운행 첫날**에 `close` (`reason: brt`). 법적 폐지일은 별도 |
| 정기 여객 영업이 없어진 구간 (海峡線 中小国～木古内) | 철도사업이 폐지되지 않아도 `close` (`reason: no_regular_service`) |
| 재해로 불통인 채 끝난 구간 | 폐지 신고까지 `suspend`로 운행 중과 같게 두고, 신고 때 `close`. `last_service`는 실제 마지막 운행일 |
| 이설인가 km 개정인가 | **역 이전을 수반하는 선로 교체**면 `relocate` (吾妻線, 常磐線 駒ケ嶺～浜吉田, 仙石線 陸前大塚～陸前小野, 菊池線). 재해 복구로 지형이 크게 바뀐 곳은 평면 위치가 같아도 교체로 침 (石巻線 浦宿～女川). 역 이전 없이 선로 모양이나 km만 바뀌면 `km_change`. 노리츠부시 안내와 같은 기준 |
| 역 위치 이동·선로 이설 | km가 그대로면 **노드를 유지**하고 `move`로 좌표만 옮김. 선로만 양 끝이 같은 병렬 edge로 둠 (`@old`, `@new`). km가 달라지면 노드 둘을 두고 `moved`로 이전일에서 기간을 가르며 같은 역 묶음으로 침 |
| 사업자만 바뀜 (국철→JR, 사명 변경, 흡수합병) | `transfer`의 `to`에 **같은 `line`** + 새 `operator`. 노선 ID 유지. 합병과 함께 노선명이 바뀌면 `rename` 추가 (新京成線 → 京成松戸線) |
| 노선이 바뀜 (3섹 전환, 노선 통합) | 새 `line` + `transfer`. 여러 노선이 하나로 합쳐져도 `transfer` (북·남 리아스선 → 리아스선) |
| 이름만 바뀜 | `rename`. 노선 ID 유지 |
| 운휴를 거쳐 이관 (도야마항선) | 재개되는 edge는 `suspend` + `transfer` + `resume`, 새로 놓은 선로는 `open` |
| 역 ↔ 신호장 전환 | 별도 이벤트 없음. 여객 취급이 끝나면 `close_stop`. `node.kind`는 가장 최근 종류만 기록 |

### 2.3 예시
**두 번에 걸친 부분 폐선 (삿쇼선)**
```yaml
# events/jr-hokkaido/sassho.yaml
- { date: 1935-10-03, type: open, operator: o_japanese_national_railways, line: l_sassho,
    edges: [n_ishikari_tobetsu..n_ishikari_numata] }
- { date: 1972-06-19, type: close, line: l_sassho, edges: [n_shin_totsukawa..n_ishikari_numata] }
- { date: 2020-05-07, type: close, line: l_sassho, last_service: 2020-04-17,
    edges: [n_hokkaido_iryo_daigaku..n_shin_totsukawa] }
- { date: 2022-03-12, type: open_stop, route: r_sassho_main, node: n_roys_town }
  # 지난 일이므로 n_roys_town은 처음부터 선로 위의 통과 지점이고, 이날부터 정차역이 됨
```
**사업자 전환 (신에츠 본선 → 시나노 철도)**
```yaml
- { date: 1997-10-01, type: transfer, edges: [n_karuizawa..n_shinonoi],
    from: { operator: o_jr_east, line: l_shinetsu }, to: { operator: o_shinano, line: l_shinano } }
```
**같은 선로에 사업자 추가 (나리타 스카이 액세스)**
```yaml
- { date: 2010-07-17, type: transfer, within: l_hokuso, edges: [n_keisei_takasago..n_inba_nihon_idai],
    to: { operator: o_keisei, line: l_narita_sky_access } }
```
**선로 이설 (아가츠마선)**
```yaml
- { date: 2014-10-01, type: relocate, line: l_agatsuma,
    close: [n_iwashima..n_naganohara_kusatsuguchi@old], open: [n_iwashima..n_naganohara_kusatsuguchi@new] }
```
> 예시 값은 검증 전입니다. `a..b`는 a부터 b까지 연속된 edge 전부(푸는 규칙은 §2.2), `@old`·`@new`는 양 끝이 같은 병렬 edge의 구분 표기입니다.

### 2.4 신호장·화물역 — 내부 전용
- 신호장·분기점·**화물역**은 **데이터 신뢰도 검증용**으로만 DB에 둡니다 (사업자 경계가 신호장에 있는 경우 등 거리·귀속 계산에 필요). 화물역은 `kind: freight`. 여객 영업 기간이 있던 역은 그 기간만 공개합니다.
- **앱 어디에서도 보이지 않게** 3중으로 막습니다.
  1. 빌드 시 앱용 DB에서 **한 번도 정차역이었던 적이 없는** 신호장·분기점·화물역의 이름·읽기를 제거 (ID와 위상 정보만 남김) → 검색 색인에도 들어가지 않음
  2. 앱의 데이터 접근 계층은 `node_public` 뷰만 사용 (**한 번이라도 정차역이었던 노드**만 노출). 역이었다가 신호장이 된 곳(石勝線 楓·東追分 등)은 사용자에게 **"폐역"**으로만 보임 — 지도의 폐역 점, 폐역 터 방문 기록 모두 가능. 지금 신호장이라는 사실은 노출하지 않음
  - "정차역인가"는 노드 전체가 아니라 **(계통, 노드)** 단위 속성. 예: 名鉄 名古屋本線이 JR 飯田線 선로를 지나는 豊橋–平井信号場 구간의 船町·下地는 JR 계통에서만 정차역 → 名鉄 역 선택기에는 나오지 않음
  3. 테스트: UI 계층에서 원본 `node` 테이블을 직접 읽는 코드가 있으면 CI 실패
- 노선도·역 선택기·지도·통계에 나오지 않습니다. 역 사이 거리는 신호장을 거쳐 합산된 값으로만 보입니다.
- **예외 하나**: 호환판 CSV에서 노선 경계가 숨은 노드일 때는 행을 나눠야 하므로 `node.export_name`(노리츠부시 표기 `[枇杷島分岐点]`)을 내보내기에만 씁니다. 화면에는 쓰지 않습니다.

### 2.5 사업자 분류
- `operator.category`: 노리츠부시 분류를 따름 — `jr`(JR각사) · `major_private`(대형사철) · `semi_major_private`(준대형사철) · `public`(공영) · `general_private`(일반사철, 3섹 포함) · `monorail` · `agt`(신교통) · `cable`(강삭) — **DB에는 유지**합니다.
- 지도는 분류와 무관하게 같은 색. 통계 화면은 전체 / 사업자별 / 노선별 / 도도부현별. 분류별 표시는 나중에 필요해지면 데이터 변경 없이 화면만 추가.

### 2.6 빌드와 검증
```
events + 뼈대  ──컴파일──▶  유효 기간·귀속·상태 (master.sqlite)
km             ──────────▶  거리 테이블 (master.sqlite)
positions/geometry ──────▶  rail.pmtiles (지도 전용)
names          ──────────▶  names.sqlite (표시 이름·별칭·검색 색인, 공개 노드만)
```
CI 검사는 네트워크 없이 돕니다. 결과는 `coverage.json`과 빌드 리포트로 나오고, 문서의 수치는 이 리포트에서 가져옵니다.

| 분류 | 검사 |
|---|---|
| 위상 | 1969-12-08 이후 모든 날짜 구간에서 영업 중인 edge가 이어지는지. 끊긴 곳은 `checks/intentional_gap.yaml`에 있어야 함 |
| 날짜 | 날짜 정합성. 범위 날짜는 양 끝 시점에서 각각 검사 |
| 수록 | 공개 노선마다 §4.1 등급을 판정, 등급 조건을 못 채우면 실패 |
| 귀속 | 영업 중인 edge마다 `edge_attr`가 1행 이상. (line, edge)당 동시 행은 1개 |
| 계통 | 끝 노드가 숨은 노드이거나 그 계통의 정차역이 아니면 `extend_to`나 그 끝을 지나는 service가 있어야 함 |
| 거리 | 노선별 총 km를 출처 값과 대조. **사업자별 합계를 공표 총 영업km와 대조** (JR 도카이 1,970.8km). 멤버십이 둘 이상인 edge는 양쪽 공식 km를 비교 |
| 순서 | 역 순서를 출처끼리 대조 |
| 이름 | 공개되는 역·노선·사업자에 한글 이름과 `source`가 있어야 함. **한글에 일본어 글자 금지**, 읽기가 다른 키의 나무위키 제목 공유 금지, 출처 있는 값이 규칙으로 조용히 떨어지면 실패 |
| ID | 배포된 ID는 추가 전용 `ids.lock`과 대조. 재사용·삭제 금지, redirect 사슬 순환 금지 |
| 라이선스 | 파일별 허용 출처 외의 값이 섞이면 실패 (§2.11) |
| 회귀 | 옛 데이터셋의 고정 기록을 새 데이터셋으로 재해석해 결과 비교. 판 간 변경량이 상한을 넘으면 사람 확인 |

### 2.7 지선 · 계통 · 중복 구간

**세 개념을 분리합니다.**
| 개념 | 정의 | 예 |
|---|---|---|
| **노선 (line)** | 공식 선로 명칭. 통계·완주의 단위 | 千歳線, 函館本線 |
| **계통 (route)** | 노선 안에서 **분기 없이 한 줄로 이어지는 역의 열**. 고유한 km 축(기점 0.0)을 가짐 | 千歳線 본선(沼ノ端→白石), 千歳線 공항지선(南千歳→新千歳空港), 函館本線 본선 / 砂原支線 |
| **edge** | 인접 노드 사이의 물리 선로. 복선·복복선은 **노선당 1 edge**로 셈. `open`·`transfer`에서 컴파일되는 집계 멤버십(`edge_attr`)으로 (노선, 사업자)에 속함 — JR은 원칙적으로 하나, 예외·사철 공동 영업 구간은 여럿 | 南千歳–新千歳空港 |

**계통 파일 (routes 모듈)** — 날짜도 역 목록도 직접 갖지 않고, **기점·종점(+필요하면 경유 노드)**만 가집니다.
```yaml
# routes/jr-hokkaido/chitose.yaml
- { id: r_chitose_main,    line: l_chitose, from: n_numanohata, to: n_shiroishi_chitose, role: main }
- { id: r_chitose_airport, line: l_chitose, from: n_minami_chitose, to: n_shin_chitose_kuko, role: branch }
# routes/jr-hokkaido/hakodate.yaml
- { id: r_hakodate_main,   line: l_hakodate, from: n_hakodate, to: n_asahikawa, via: [n_komagatake], role: main }
- { id: r_hakodate_sawara, line: l_hakodate, from: n_onuma, to: n_mori, via: [n_oshima_sawara], role: branch }
# routes/jr-central/tokaido.yaml — 공식 계통. 본선과 같은 구간을 달려도 자기 edge를 가짐
- { id: r_tokaido_mino, line: l_tokaido, from: n_ogaki, to: n_mino_akasaka, role: branch }
# routes/meitetsu/inuyama.yaml — 공식 기점이 숨은 노드
- { id: r_inuyama_main, line: l_meitetsu_inuyama, from: n_biwajima_junction, to: n_shin_unuma,
    extend_to: [n_higashi_biwajima] }
```
- 빌드는 각 시점에서 **그 노선에 속한 edge만 남긴 부분 그래프**에서 `from → (via) → to` 경로를 찾습니다. 같은 양 끝의 신칸센 선로나 이관된 구간은 후보가 되지 않습니다. 결과는 파생 테이블 `route_edge`(계통, 순번, edge, 기간)입니다.
- **공식 영업km에 따로 잡힌 계통은 같은 구간을 달려도 자기 edge를 둡니다** (`route_only`). 東海道本線의 美濃赤坂線 大垣~美濃赤坂 5.0km와 新垂井経由 大垣~関ヶ原 13.8km가 그렇습니다. 둘을 모두 세어야 JR 도카이 합계 1,970.8km가 맞고, 노리츠부시도 같습니다. 본선으로 탄 기록은 이 계통을 채우지 않습니다. `route_only`가 있는 edge는 그 계통의 경로 탐색에만 쓰입니다.
- **CI 검사**: 모든 날짜 구간에서 각 노선의 집계 구간이 계통들로 **겹침·빠짐 없이** 나뉘는지.
- 역 신설·부분 폐지가 있어도 계통 파일은 고칠 필요 없음. 기점·종점 쪽 폐지는 빌드가 그 시점에 영업 중인 범위로 자동으로 잘라 냄. 공식 단위가 시대마다 달라 경로가 달라지면 계통을 새로 둠.
- **`extend_to`**: 계통 끝이 숨은 노드이면 화면 끝의 역에서 더 이어 고를 수 없습니다. 그 너머의 역을 적어 두면 선택기에 함께 보이고, 고르면 저장할 때 그 역이 속한 계통으로 leg를 나눕니다. `route_stop`에 `is_extension` 행으로 들어가고 km는 표시하지 않습니다. 정차하지 않는 공개 역에서 끝나는 계통도 같습니다.
- **순환·올가미형 계통** (大江戸線 등. 大阪環状線과 名城線은 공식 노선이 열려 있어 순환 입력은 운전 계통이 맡음): `closed: true`. 순환은 기점과 종점이 같고, 올가미는 기점 또는 종점이 자기 계통의 중간역입니다 (大江戸線 都庁前). 역 순서는 (계통, 순번)으로 저장해 같은 역이 두 번 나와도 됨. 입력은 §8 "순환 입력". `via` 필수. 시대에 따라 닫히는 계통은 `closed_from`에 날짜를 적음.

**지선 유형별 처리**
| 유형 | 처리 |
|---|---|
| 역에서 갈라지는 지선 (千歳線 공항지선) | 지선 계통의 기점 = 분기역 노드. 분기역은 두 계통에 모두 나타남 |
| 역이 아닌 지점에서 갈라지는 지선 (名鉄 枇杷島分岐点 등) | 분기점을 `kind: junction` 노드로 둠 → **신호장과 같이 화면에 노출 안 함**. 끝 구간 입력은 `extend_to`로 처리 |
| 같은 노선 안의 병행 경로 (函館本線 본선 vs 砂原支線, 둘 다 大沼–森) | 계통이 달라 구분됨. 그래서 기록에는 **계통 ID를 함께 저장** (노선 + 역 두 개만으로는 경로가 모호) |
| 중간 폐지로 끊긴 노선 (根室本線) | 계통은 그대로 하나. 빌드가 시점별로 "현재 이어진 덩어리"를 계산하고, 화면은 한 노선도 안에서 폐지 구간을 3단계로 그림 (§8.1) |
| 다른 노선과 겹치는 구간 (中央本線의 代々木–新宿 = 山手線) | 그 노선의 계통에 넣지 않음. 이어서 타는 입력은 운전 계통으로 (아래 "중복 구간") |

**중복 구간 — 탑승 기록은 "지나가는 모든 노선"에 붙지 않는다**

기록은 항상 **(기록한 노선, edge)** 한 쌍에만 붙습니다. 같은 선로를 여러 노선이 지나가도, 기록하지 않은 노선은 탄 것으로 치지 않습니다.

| 층 | 무엇으로 판단 | 결과 |
|---|---|---|
| **지도** | 물리 edge | 어느 노선으로 탔든 그 선로는 파랑 |
| **통계·완주** | (노선, edge) 집계 멤버십 = `edge_attr` 행 | 기록한 노선에만 크레딧 |

**집계 멤버십 규칙** (노리츠부시 = 『鉄道要覧』 기준, 로그인 세션에서 확인)
1. **JR은 한 구간을 한 노선에만 집계.** 代々木–新宿은 山手線에만 있음. 그래서 노리츠부시의 中央本線은 `新宿～塩尻` 211.8km + `(神田-代々木)` 8.3km + `(辰野経由)`로 이루어지고, 東京–神田(東北本線)과 代々木–新宿(山手線)은 中央本線의 분모에 **처음부터 없음**.
2. **JR 예외 4곳**은 두 노선 모두 집계: 小倉–西小倉(日豊/鹿児島), 金山–名古屋(中央/東海道), 今宮–新今宮(関西/大阪環状), 鴫野–放出(片町/おおさか東).
3. **사철은 같은 구간을 여러 사업자가 여객 영업하면 사업자마다 따로 집계** (예: 京成 成田空港線과 北総鉄道가 같은 선로를 씀). 선로만 가진 제3종 사업자는 집계 안 함. 공식 명칭이 같아도 여객 사업자마다 별도 line입니다. 기록은 사업자를 따로 저장하지 않고 노선으로 구분합니다.
4. **같은 사업자의 중복 구간은 공식 소속 노선 하나에만 집계.** 阪急 梅田–十三은 공식으로 宝塚本線(증설선 포함)에 속하고, 京都本線의 공식 기점은 十三. "梅田→淡路" 같은 입력은 운전 계통으로 받음. 東京メトロ 有楽町線·副都心線 공용 구간도 같은 유형.

**크레딧 예시**
| 실제 탑승 | 기록 방법 | 크레딧 |
|---|---|---|
| 中央線 쾌속, 東京→新宿 | 운전 계통 "中央快速線"으로 입력 | 東北本線 東京–神田 1.3 · 中央本線 神田–代々木 8.3 · 山手線 代々木–新宿 0.7 |
| 山手線 전차, 代々木→新宿 | 山手線 | 山手線 0.7 |
| 中央本線 전차, 金山→名古屋 | 中央本線 | 中央本線만. 東海道本線은 안 탄 것 |
| 京成 스카이라이너, 京成高砂→成田空港 | 京成 成田空港線 | 京成만. 같은 선로의 北総鉄道는 안 탄 것 |

첫 줄처럼 中央線 열차로 代々木–新宿을 지나도 山手線에 크레딧이 가는 것은 "노선 = 선로의 공식 명칭"이라는 노리츠부시 규칙 그대로입니다. 입력 화면에서 이 분해 결과를 보여 줘서 사용자가 혼동하지 않게 합니다.

**운전 계통 (services 모듈) — 입력 편의용**
노리츠부시의 "路線名で検索"은 공식 노선이 아닌 통칭·운전 계통(예: `中央快速線 東京～高尾`)으로 입력하게 하고, 저장할 때 위 표처럼 공식 노선 구간으로 쪼갭니다. 같은 구조를 둡니다.
```yaml
# services/jr-east/chuo-rapid.yaml
id: s_chuo_rapid
closed: false                # 순환 운전이면 true (야마노테선 일주)
parts:                       # 공식 계통 구간을 이어 붙인 것
  - { route: r_tohoku_main,   from: n_tokyo,    to: n_kanda_chuo_main }
  - { route: r_chuo_kanda,    from: n_kanda_chuo_main,    to: n_yoyogi }
  - { route: r_yamanote_main, from: n_yoyogi,   to: n_shinjuku }
  - { route: r_chuo_main,     from: n_shinjuku, to: n_takao }
stops: [n_tokyo, n_kanda_chuo_main, n_ochanomizu, n_yotsuya, n_shinjuku]   # 생략하면 모든 정차역. 예시는 앞부분만
```
- 운전 계통은 **통계 단위가 아님**. 구성이 시대에 따라 달라지면 날짜가 붙은 판을 둠 (北陸本線 경유 はくたか처럼 지금은 없는 경로를 옛 날짜로 입력하기 위해). 날짜 모름이고 판이 여럿이면 고르게 함
- `parts`는 노선이 아니라 **계통**을 가리킵니다. 日暮里→赤羽(王子/尾久)처럼 경로가 둘인 곳을 저장 시 틀리지 않게 하기 위해서입니다
- 쇼난신주쿠라인처럼 끝이 갈라지는 계통은 service 2개로 정의
- 공식 야마노테선은 品川~新宿~田端의 열린 20.6km입니다. 일주 입력은 `closed: true`인 service가 맡습니다
- 검색에서 공식 노선과 운전 계통을 함께 보여 줌. 기록에는 고른 운전 계통 ID를 남겨 "츄오 쾌속선으로 탑승"처럼 표시
- 이 구조 덕분에 노선(routes)에는 그 노선이 집계하는 edge만 넣으면 됨 → 中央本線 계통은 노리츠부시처럼 `神田–代々木`, `新宿–塩尻`, `辰野経由`로 나뉨

**화면**
- 노선 상세: 계통마다 한 줄씩 세로 노선도, 분기역에 "← 본선 / 공항지선 →" 연결 표시
- 역 선택기: 노선을 고르면 상단에 계통 전환 칩 (`본선 · 공항지선`). 계통이 하나면 칩 없음
- 통계: 노선 단위 합산 + 노선 상세에서 계통별 진행률

### 2.8 논리 검토로 보완한 규칙
설계를 실제 사례에 대입해 보며 빈틈을 메운 규칙입니다.

**A. 데이터 정정과 실제 변화를 분리**
- `events/`는 **현실에서 일어난 변화**만 기록. 우리 데이터의 실수(같은 역을 두 ID로 만든 경우 등)는 이벤트가 아니라 git 커밋으로 고침.
- ID를 합치거나 없앨 때는 `redirects/`에 남김. 형식과 절차는 §2.10.

**B. 노드, 역 묶음, 환승 묶음**
| 단위 | 뜻 | 쓰는 곳 | 예 |
|---|---|---|---|
| node | 한 사업자(또는 공동 사용하는 사업자들)의 역 시설 | 기록의 출발·도착 | JR 新宿, 小田急 新宿 |
| group | **같은 역**으로 치는 node 묶음. 같은 이름이 기본 (N02 그룹 코드와 같은 개념) | 방문 역 수, 지도의 역 점·캡슐, 역 방문 기록 | 新宿 |
| hub | **걸어서 갈아탈 수 있는** node 묶음. 이름이 달라도 됨 | 기록 화면의 환승 표시 | 히메지 + 산요히메지 |

- hub는 group을 대체하지 않습니다. 합치면 히메지와 산요히메지가 방문 역 하나로 줄어듭니다.
- 공동 사용역은 노드 하나에 노선별 이름을 둡니다 (§9.2).
- 같은 사업자의 같은 역은 신칸센·재래선, 떨어진 승강장까지 한 node입니다. 경로 탐색이 노선별 부분 그래프라 없는 직통 경로가 생기지 않습니다. 사업자가 다르면 별도 node + 같은 group + hub입니다 (福井의 JR 서일본과 하피라인 후쿠이).
- 방문 화면에서 원하면 group 안의 특정 node까지 지정.

**C. 영업km는 구간별 값 하나가 원본**
- 원본은 `km/`의 **구간(edge)별 길이**이고, 바뀌면 그 구간에 `km_change` 이벤트. 계통의 누적 km(0.0, 3.4, 8.3 …)는 표시용으로 빌드 시 계산 → 진실의 출처가 하나.
- 자료(위키백과 노선도, 사업자 공표 자료)는 누적 km로 되어 있으므로, 가져오기 도구가 차이를 구해 구간 길이로 바꿔 저장. 『鉄道要覧』 내용은 직접 확인하지 못해 근거로 쓰지 않습니다.
- km를 모르는 신호장·분기점은 선로망에 넣지 않고 품질 메모로만 둠. 단, **경계 노드**(사업자·노선·폐지 구간·도도부현 경계)가 되는 노드는 km 필수 (CI 검사).

| 쓰임 | 어느 시점의 km |
|---|---|
| 현행 분모 | 지금 |
| 역대 분모 | 영업 중이면 지금, 끝난 단위는 종료 직전 (노리츠부시와 같음) |
| 특정 연도 Y | 그해 마지막 영업일 |
| 탑승 거리 | 탑승일. 날짜가 범위이면 `effective_hi` 시점 |
| 입력 화면 표시 | 고른 탑승일. 날짜 모름이면 지금 또는 종료 직전 |

**D. 탑승 기록의 해석은 탑승일 기준**
- 기록(노선 + 계통 + 역 + 날짜)을 구간 목록으로 펼칠 때 **탑승일에 존재하던 선로망**을 씀. 2010년 기록은 이설 전 선로로, 2020년 기록은 이설 후 선로로.
- **`route_id`는 항상 저장합니다.** 저장 시 경로가 하나였어도 나중에 병행 계통이 추가될 수 있습니다.
- 날짜를 몰라 경로가 둘 이상이면 저장 시 물어 `resolve_as_of`(이 날짜의 선로망으로 펼침) 또는 `direction`을 저장. 답은 그 구간의 선형 목록과 `모름`입니다 (이설이 한 번이면 `옛 선로` / `새 선로` / `모름`). 고른 선형은 날짜로 저장하므로 나중에 이설이 더 생겨도 뜻이 바뀌지 않습니다.
- `모름`이면 `ride_leg.resolve_unknown`을 저장하고 상태를 `partial`로 둡니다. 공통 구간만 크레딧을 주고 나머지는 확인 필요로 둡니다. 데이터셋이 갱신돼도 다시 묻지 않습니다.
- 펼친 결과는 캐시 테이블에 둡니다. 데이터가 바뀌면 다시 계산. 원본은 언제나 노드와 입력한 날짜.

**E. 사업자 전환과 "기록 승계" 설정의 정확한 의미**
- `transfer`는 선로를 닫지 않음 (`edge_life`는 그대로). 새 집계 멤버십 행을 만들고 옛 행과 같은 `lineage_id`로 묶음. `lineage_id`는 비어 있지 않습니다. 변화 없는 노선은 단독 사슬입니다.
- **승계 켬 (기본)**: 완주 단위 = (lineage, edge). 하나의 단위이므로 역대 분모에도 **한 번만** 들어감. 1990년 JR 시절 탑승도, 2020년 しなの鉄道 탑승도 같은 단위를 채움. 이 단위는 지금의 노선 이름(しなの鉄道線)으로 표시.
- **승계 끔 (노리츠부시 방식)**: 완주 단위 = (`carryover_group`, edge). 새 값은 **국철·JR에서 다른 사업자로 넘어갈 때만** 생깁니다. 노리츠부시 안내가 JR→사철은 폐지·신규 개업으로, 사철→사철은 승차 기록 승계로 정하고 있기 때문입니다. 국철→JR, 사철 사이의 이관과 합병, 사명 변경, 개칭, 노선 통합, 같은 노선의 부활은 값을 유지합니다. 빌드가 `transfer`에서 계산하므로 손으로 입력하지 않습니다. 탑승은 **탑승일의 단위**에만 크레딧. JR 信越本線 단위(~1997)는 폐선처럼 역대 기준에만 남음 (노리츠부시 타임머신의 信越本線 横川～篠ノ井와 같은 모양). 그래서 끔에서는 이관 구간이 역대에 두 단위로 들어갑니다. 의도한 동작입니다.
- 두 방식의 분모를 모두 미리 계산 → 설정을 바꿔도 즉시 반영.
- 사철 공동 영업 구간처럼 멤버십이 여럿인 구간은 **기록한 노선의 lineage만** 따라감 (다른 사업자 멤버십으로 번지지 않음).

| 입력 | `lineage_id` | `carryover_group` |
|---|---|---|
| `open` | 새 사슬 | 새 값 |
| `transfer` from+to, 국철·JR → 타사 | 유지 | 새 값 |
| `transfer` from+to, 그 밖 (국철→JR, JR 각사 사이, 사철 사이) | 유지 | 유지 |
| `to`만 (사업자 추가) | 새 사슬 | 새 값 |
| `from`만 (사업자 철수) | 그 행 종료 | 그 행 종료 |
| `open` + `continues` (폐선 뒤 재개) | 유지 | 옛 사업자가 국철·JR이고 새 사업자가 타사면 새 값, 아니면 유지 |

`o_japanese_national_railways`의 분류는 `jr`입니다.

**F. 지선·노선을 넘나드는 탑승, 숨은 노드가 경계인 경우**
- 같은 노선 안에서는 계통을 넘어 경로를 자동 탐색 (예: 지선 역 → 본선 역). 저장은 분기역에서 나눠 계통마다 한 leg로 합니다.
- 노선 경계가 숨은 노드(분기점·신호장)인 경우 (名鉄名古屋→犬山: 名古屋本線 → 枇杷島分岐点 → 犬山線): 고른 두 역의 사이를 저장 시 숨은 노드에서 자동으로 legs로 나눔. 화면의 분해 결과에는 "名古屋本線 ○km · 犬山線 ○km"만 보이고 분기점 이름은 나오지 않음. 입력 경로는 service 또는 `extend_to`입니다.

**G. 순환 계통**
- `closed: true`. 역 순서는 (계통, 순번)으로 저장. 순환 계통의 탑승은 방향(`seq_up`/`seq_down`)을 함께 저장. leg 하나는 한 바퀴까지이고, 두 바퀴 이상은 leg를 바퀴 수만큼 저장합니다.

**H. 운전 계통은 저장 시점에 분해**
- 운전 계통으로 입력한 기록은 **저장할 때** 공식 노선 구간으로 분해해 legs로 저장. 나중에 운전 계통 정의가 바뀌어도 과거 기록은 바뀌지 않음. `service_id`는 표시용으로만 남음.
- 탑승일에 맞는 운전 계통 판을 골라 분해.

**I. 데이터 변경과 기록**
- 탑승 기록(ride + legs)은 하나의 묶음입니다. leg에는 개별 삭제 표시가 없습니다.
- 삭제와 되살리기도 편집처럼 `updated_at`을 올립니다.
- 구간 끄기(§8.2)는 기록을 고칩니다. 조각은 평범한 기록입니다.
- 데이터가 바뀐 뒤 다시 계산한 결과가 이전과 다르면 사용자에게 **변경 내역**을 보여 줌 ("데이터 정정으로 ○○선 탑승 거리가 0.3km 바뀌었어요").
- 복원한 기록이 지금 판에 없는 ID를 가리키면 버리지 않고 `unknown_ref`로 두고 갱신을 안내합니다.
- CSV 등으로 가져온 행은 내용 기반 고정 ID(UUIDv5, 입력은 §10.2)를 써서, 같은 파일을 다시 가져와도 중복되지 않음.
- 같은 (날짜, 경로, 시각)의 기록은 중복 후보로 보여 줍니다. 왕복과 구분할 수 없으므로 자동으로 합치지 않습니다.

**J. 특정 연도 완주율과 날짜를 모르는 기록**
- 분모: **Y년 중 하루라도 영업한** 단위 (12월 31일 하루만 보면 그해에 폐지된 구간의 "마지막 승차"가 어느 해에도 잡히지 않음). 연중 불통인 구간도 현행과 같게 포함. 이설이 있는 해에는 옛 선로와 새 선로가 함께 들어가 분모가 커지며, 화면에 그렇게 설명합니다.
- 분자: 그 단위의 기록 중 **유효 날짜 범위의 끝이 Y년 12월 31일 이전**인 것.
- 기록의 유효 날짜 범위 = 사용자가 입력한 범위 ∩ 각 leg의 (노선, edge) 멤버십 기간 ∩ 승하차역 정차 기간(`*_alighted`가 참인 끝만, 그날 맡은 노선의 계통에서 찾음). 계산된 날짜가 없는 기록은 기록을 만든 날 이전으로 한 번 더 자릅니다. 예: 날짜 없이 가져온 노리츠부시 기록(2026년에 가져옴)은 최소한 "2026년까지는 탔다"로 집계되고, 2018년 폐지된 三江線 기록이면 "2018년까지는 탔다"가 됨. 영업 기간이 끊긴 경로는 구간 합집합으로 검증합니다.
- 교집합이 비면 저장을 막지 않습니다. 저장, 가져오기, 재해석 모두 같은 규칙으로 날짜 모름이 되고(§4.6), 입력한 값은 `date_input`에 남습니다. 데이터가 정정되면 재해석이 날짜를 되살립니다.
- 저장과 날짜 수정 때 `line_id`·`route_id`를 탑승일의 멤버십으로 맞춥니다. 날짜 수정은 사용자 수정이고, `resolve_as_of`, `resolve_unknown`을 지운 뒤 다시 펼칩니다. 재해석으로 바뀐 노선은 파생 값이며 집계와 표시는 그 값을 씁니다 (ARCHITECTURE §3.4). 이관 날짜에 걸친 범위 날짜면 입력한 노선을 유지합니다.
- 현행 분모는 빌드 시 고정하지 않고, 이벤트 날짜마다 바뀌는 값을 미리 구간별로 계산해 두고 **앱 실행 시 오늘 날짜로 선택** (예정된 개업·폐지가 날짜가 지나면 자동 반영). 합계는 읽을 때 `ride_edge`와 `denominator_unit`을 결합해 구합니다. 폐지일이 지나도 100%를 넘지 않습니다.

**K. 도도부현별 통계**
- 도도부현 경계를 넘는 구간(倶利伽羅–石動 등)은 경계 지점에 숨은 `pref_boundary` 노드를 두고 km를 기록 → 통계는 지도 선형 없이도 계산됨.
- 경계 km는 데이터 작성 시 선형으로 한 번 구해 **값으로 저장** (실행 중에 선형을 쓰지 않음). 선형이 없는 기록 가능 등급 노선은 구간 km를 양 끝 역의 도도부현에 반씩 나누고 "근사"로 표시.

**L. 지도 필터와 통계의 일치**
- 전체 지도: 물리 구간 기준 (어느 노선으로든 탔으면 파랑).
- **노선 단독 보기**: (노선, 구간) 크레딧 기준. 金山–名古屋를 中央本線으로만 탔다면 東海道本線 단독 보기에서는 미승으로 보임.
- **`승차만` 보기 (사용자 지시, 2026-11-02)**: 지도 전체에서 탄 선과 지나간 역만 남깁니다. 미승 구간만 보는 기능을 대체합니다.

**M. "발로 밟은 역" 판정**
- 승하차역 = `from_alighted`·`to_alighted`가 참인 기록 끝 + 사용자가 "여기서 갈아탐"으로 표시한 역. 운전 계통 분해로 생긴 leg 경계(神田·代々木 등)는 통과 역으로 침.
- 손으로 입력한 끝은 참입니다. 구간 탭, 구간을 잘라 생긴 끝, CSV 가져오기는 거짓이고 통과로 칠합니다. CSV는 가져온 뒤 일괄로 참으로 바꿀 수 있습니다.
- 통과 판정은 그 노드를 물리적으로 지났는지로 합니다. 재해석 뒤 경로 밖이 된 "갈아탄 역"은 무시합니다.
- 방문 역 수 통계 = 역 방문 기록 ∪ 승하차역 (중복 없이, group 단위).

**N. 재해석 상태**
| `resolve_status` (로컬) | 뜻 |
|---|---|
| `ok` | 정상 |
| `partial` | 이설 구간에 `모름`으로 답함. 공통 구간만 크레딧 |
| `needs_input` | 경로가 둘 이상이라 사용자 답이 필요 |
| `unknown_ref` | 데이터셋에 없는 ID (오래된 기기, 미수록 CSV 행) |
| `invalid` | 어떤 날짜로도 경로가 없음 (묘비 처리된 역, 계통에서 사라진 구간) |
| `error` | 앱이 이 기록을 계산하지 못함. 다른 기록의 계산은 계속되고, 규칙이나 판이 바뀌면 다시 계산 |

- `ok`와 `partial`이 아닌 기록은 완주에서 빼고 `확인 필요 n건 · m km`로 표시합니다. `partial`의 나머지 구간도 여기에 셉니다. 원본은 지우지 않습니다.
- 가져온 행의 원문은 `ride.import_raw`에 보존합니다.

**O. 분모 등급**
| `edge_attr.denominator_class` | 뜻 |
|---|---|
| `normal` | 분모 포함 |
| `outside` | 사철 1969-12-08~1999 폐선 (§4.6). 기록은 되지만 분모 밖 |
| `extra` | 별선·단락선. 기록은 되지만 분모 밖 |

- **분자 = 분모 단위 ∩ 탄 단위.** 세 기준 모두 같습니다. 분모 밖 구간의 km는 화면에 따로 보여 주지 않습니다.
- 등급은 기간별 행에 있어 같은 노선 안에서도 달라질 수 있습니다 (기간이 정해진 별선, 정기 열차가 없어진 구간). 변경은 `set_class`로 적습니다. `line.rule_class`는 기본값이고 `shinkansen`은 `normal`입니다. `outside`는 빌드가 사철 폐지일로 계산합니다.
- 한 단위에 등급이 다른 행이 섞이면, 역대는 행 중 하나라도 `normal`이면 포함하고, 현행은 오늘 행, 특정 연도는 그해 행의 등급을 씁니다. 승계 켬·끔 모두 같습니다.
- 전 구간이 분모 밖인 노선은 전체 통계에 들어가지 않습니다. 그 노선의 상세 화면은 노선 자체의 km로 진행률을 보여 줍니다.
- `extra`는 노리츠부시처럼 승차 km와 승차율에서 뺍니다. 다만 실제로 달린 누적 탑승 거리에는 넣습니다.
- 사철 목록이 완성되면 한 번에 `normal`로 옮기고 변경 내역으로 안내합니다.

### 2.9 환승·분기·승계 모듈
서로 다른 사실을 한 파일에 섞지 않습니다.

```yaml
# hubs/himeji.yaml — 걸어서 갈아탈 수 있는 역 묶음
id: hub_himeji
nodes: [n_himeji, n_sanyo_himeji]
valid: [1910-XX-XX, ongoing]
source: [station_database, "wikipedia:<revid>"]
verified: false

# junctions/jr-west/sanyo.yaml — 선로가 갈라지는 곳. 화면마다 한 행
- line: l_sanyo
  other: l_bantan
  at: n_himeji            # 역이 아니면 edge: e_000123
  side: up                # 이 노선의 위쪽으로 달리는 열차가 곧장 들어가는 쪽. 모르면 생략
  valid: [1894-XX-XX, ongoing]
  source: "wikipedia:<revid>"
  verified: false

# junctions/tokyu/toyoko.yaml — 끝 역에서 다른 노선으로 이어지는 곳. 사업자 무관
- line: l_tokyu_toyoko
  other: l_fukutoshin
  at: n_shibuya_tokyu
  continue: true
  valid: [2013-03-16, ongoing]

# lineage/futamata.yaml — 사슬에 고정 ID를 줄 때만. 사슬은 transfer에서 나옴
id: lg_futamata
head_line: l_jnr_futamata   # 사슬의 첫 노선. 표시 이름은 names/에
```

**표시 결정표**: (역, 상대 계통) 한 쌍의 표시는 하나입니다. 같은 노선의 지선은 `other_route`로 가리킵니다. 위에서부터 처음 맞는 행을 씁니다.

| 순서 | 조건 | 표시 |
|---|---|---|
| 1 | 기록 중인 노선의 끝 역이고 그날 유효한 `continue` 행이 있음 | 끝에서 이어짐 |
| 2 | **이 역에**, 또는 이 역이 위쪽 역인 역 사이 지점에 그날 유효한 junction이 있음 | 분기. `side` 없으면 아래로 |
| 3 | 같은 node 또는 같은 hub에 속함 | 환승 캡슐 |

- 양 끝이 같은 줄기에 닿는 노선(고텐바선, 텐류하마나코선 등)은 역마다 위 표를 따로 적용합니다. 한쪽이 곡선, 다른 쪽이 캡슐일 수 있습니다.
- **`side`의 뜻**: 위쪽 역 A와 아래쪽 역 B 사이에서 C로 갈라질 때, A→C는 곧장 가고 B→C는 되돌아야 하면 `down`, 반대면 `up`. 위키의 `ABZg` 그림이 이 사실을 그린 것입니다.
- **방향 기준**: 위아래는 그 화면의 계통 순서(`seq`)입니다. 위키 문서의 진행 방향이 계통 순서와 반대이면 파이프라인에서 `side`를 뒤집습니다. 상대 노선 화면의 값은 별도 행입니다.
- 앞서 제안한 `transfers/*.yaml`은 쓰지 않습니다. 노선 쌍마다 적으면 8개 노선이 모인 역은 28행이 필요하지만, hub는 한 줄이면 됩니다.
- 사실만 기록합니다. 위키 문장과 그림 파일은 넣지 않고, `source`에 문서 판(revid)을 남깁니다.
- hub와 junction이 비어 있어도 기록·통계는 동작합니다. 입력 화면의 표시만 줄어듭니다.

**승계 사슬**: `transfer`를 이어 컴파일합니다. 출처를 하나로 두어 어긋날 일이 없습니다. 사슬은 (노선, edge) 단위라 신에츠 본선처럼 구간마다 후계가 달라도 표현됩니다. 폐선 뒤 다른 회사가 다시 여는 경우는 `open`에 `continues: <옛 line>`을 적습니다.

**이관과 부활의 판정**
| 경우 | 데이터 | 선 상태 | 이름 |
|---|---|---|---|
| 이관 (후타마타선 → 텐류하마나코 철도) | 새 `line` + `transfer` | 끊긴 적 없음, 현행 | 지금 이름 + 옛 이름 병기 |
| 개칭 | `rename` | 현행 | 위와 같음 |
| 통합 (북리아스선·남리아스선 → 리아스선) | 새 `line` + `transfer` | 현행 | 위와 같음 |
| 부활 (영업 중단 후 같은 선로 재개) | `close` 뒤 같은 edge에 `open` | 현행, 중단 기간은 기록 불가 | `~폐지 연도`, `재개 연도~`로 병기 |
| 일부만 이관 | 구간별 `transfer` | 이관 구간만 현행 | 가지의 첫 구간 상태를 따름 |
| 이관 후 폐지 | `transfer` 뒤 `close` | 폐선 | `1989~2006`을 폐선색으로 |
| 사업자 철수 | `from`만 있는 `transfer` | 그 노선 구간만 폐선 | `1968~2010` |
| 완전 폐지 | `close` | 폐선 | 옛 이름만 |

원자료의 `closed` 값은 쓰지 않고, 선로와 멤버십의 상태로 계산합니다. station_database가 폐선으로 적은 1970년 이후 노선 중 42개는 다른 노선이 같은 역을 이어 달립니다 (같은 역 75% 이상 기준의 후보, 오판 2건을 뺀 수치, 전수 확인 전).

### 2.10 원본 소유권과 ID 규칙
**세 층으로 나눕니다.** 사람이 확인한 값이 재생성으로 사라지는 일을 막기 위해서입니다.

| 층 | 내용 | 누가 씀 |
|---|---|---|
| `imports/` | 원본 스냅샷과 `sources.lock`(URL, 판, 날짜, 해시). 위키는 revid별 렌더링 HTML, OSM은 지역 추출본 | 수집 도구 |
| `candidates/` | 스크립트가 만든 후보 | 기계. 언제든 덮어씀 |
| `data/source/` | 원본 | **사람.** 기계는 diff 제안만 함 |

- station_database, 위키, 나무위키는 **시드로 한 번 들여온 뒤** 변경 감지 용도로만 씁니다. 출처가 사라지거나 형식이 바뀌어도 앱 데이터는 멈추지 않습니다.
- 손 보정은 스크립트 안의 표가 아니라 `data/source/`의 파일에 둡니다.
- 빌드는 `tools/`의 스크립트로 고정하고 의존성을 잠급니다. CI는 네트워크를 쓰지 않습니다.

**뼈대 데이터의 역할**
| 자료 | 역할 |
|---|---|
| station_database | 역·노선·읽기·좌표 시드. 노선 단위가 게임 기준(`JR常磐線(上野～取手)`)이라 공식 노선으로 다시 묶음 |
| 위키 노선도 | 공식 노선의 역 순서, km, 분기, 환승 후보 |
| N02 | 정밀 선형과 역 묶음. 역 순서·km·안정된 노선 ID는 없어 뼈대로 쓰지 않음 |
| 사업자 공지 | 3월 개정 감지와 신역 사실 확인 |
| 노리츠부시 | 노선 단위, km, 폐선 목록의 대조 기준. 로그인 세션에서 읽기 전용, 저속 |

**ID 형식**: 불투명한 값으로 취급합니다. 파싱하지 않고, 이름이 바뀌어도 바꾸지 않습니다. 외부 키(Wikidata QID, N02 코드)는 별도 열에 둡니다.

| 종류 | 형식 | 예 |
|---|---|---|
| 노드 | `n_로마자`, 같으면 `_사업자` | `n_himeji`, `n_nakanoshima_keihan` |
| 역 묶음 / 환승 묶음 | `g_` / `hub_` | `g_himeji`, `hub_himeji` |
| 사업자 / 노선 | `o_` / `l_` | `o_jr_east`, `l_sanyo` |
| 계통 / 운전 계통 | `r_` / `s_` | `r_chitose_airport`, `s_chuo_rapid` |
| edge | `e_` + 일련번호. 사람은 `a..b`로 가리킴 | `e_000123` |
| 승계 사슬 / 열람 전용 | `lg_` / `a_` | `lg_futamata`, `a_wakkanai_sanbashi` |

- **ID는 재사용하지 않습니다.** 노드, 노선, 계통, 운전 계통, 사업자, 열람 전용 ID는 추가 전용 `ids.lock`으로 관리합니다. 첫 공개 전에 시드를 동결하고 이후 ID는 `data/source`에 고정됩니다 (ARCHITECTURE §4.2). edge, 역 묶음, 승계 사슬 ID는 사용자 기록에 저장하지 않습니다.

**redirect 규칙**
| 경우 | 처리 |
|---|---|
| 1:1 정정 | `옛 ID → 새 ID` |
| 1:N 분리 (노선 분리) | `(옛 ID, 문맥 line)` 키 또는 순서 있는 목록. 못 풀면 `needs_input` |
| 대상 없는 삭제 (잘못 만든 역) | 묘비 항목. 기록은 `invalid` |
| 정정으로 비공개가 된 역을 가리키는 기록 | 기록용 표시 이름 유지 |
| 여러 판을 건너뛴 갱신 | 사슬을 압축해 적용. 순환은 CI에서 차단 |

redirect는 **읽을 때만** 적용하고 사용자 기록의 원본 ID를 다시 쓰지 않습니다. 동기화할 때 기기마다 판이 달라도 안전합니다.

**변경 유형별 도구**
| 도구 | 하는 일 |
|---|---|
| `new-station` | 노드, `split-edge`, `open_stop`, km, 좌표, 이름 후보, hub 후보를 한 번에 만들고 체크리스트 출력 |
| `split-edge` | 옛 edge를 은퇴시키고 두 새 edge로 나눠 기간 행을 만듦. 사용자 기록은 노드를 저장하므로 redirect가 필요 없음 |
| `transfer-section` | 신선 개업과 병행 재래선 이관처럼 여러 모듈을 함께 고치는 변경의 초안 생성 |
| `diff-sources` | 새 스냅샷과 `data/source/`를 비교해 변경 후보 목록 작성 |

이름 파일을 나누면 라이선스 표기가 분명해지고, 이름만 고치는 갱신이 쉬워지며, 나중에 출처별로 값을 바꿀 수도 있습니다.

OSM은 두 갈래로 나눠 씁니다. 2005년 이전 폐선의 선형은 N02에 없으므로 OSM 선형을 별도 파일로 배포합니다. OSM 선형과 그 선에 맞춘 점은 `master.sqlite`, `rail.pmtiles`와 섞지 않고 이 파일에만 둡니다. 역 점에는 이름과 연도가 함께 들어갑니다. 역의 이름과 위치, 개업 연도는 사실이고 옛 자료로도 확인할 수 있으므로 어느 파일에서나 사실 정보로 다룹니다 (사용자 결정, 2026-11-03). `node_position`에는 OSM 값을 넣지 않습니다. 빌드는 OSM 선의 유무를 `closed_section.map_visible`, 위치 미확인 표식, N02 경로 선택의 판정에 씁니다. 좌표를 옮기지 않는 사실 판정이므로 유지합니다. 분기 방향 대조는 로컬 QA로만 쓰고 결과를 공개 필드에 넣지 않습니다. `verified`는 **사람이 확인했다**는 뜻으로만 씁니다.

- 노드는 사업자별입니다. JR 계열은 국철·JR 여객 6사를 하나로 봅니다. 이관 구간은 같은 노드를 씁니다.
- 현행 노선의 옛 역은 노리츠부시에 없는 경우가 많습니다 (2005년 전 폐역). 위키 노선도에 km와 폐지 연도가 있으면 그 위치에 노드를 넣어 폐역으로 표시합니다. km가 없으면 열람 전용입니다.
- 공식 부품(`東海道本線 (美濃赤坂線)`)은 계통 하나이고, 중간 폐지로 나뉜 부품은 이어서 한 계통으로 만듭니다.
- 위키 문서만으로는 기록 가능 노선을 자동으로 만들지 않습니다. 폐지일을 본문에서 정규식으로 추정하면 다른 사건의 날짜가 들어가기 때문입니다. 기록 가능 옛 폐선은 station_database에 폐지일이 있거나 `old_hand.json`에 옮긴 노선뿐이고, 나머지는 열람 전용입니다.
- 옛 폐선의 구간별 개업·폐지·휴지는 문서를 읽어 `old_history.json`에 옮깁니다. 법적 폐지가 기준일 전인 구간은 생성기가 뺍니다.
- 역 개업일·폐지일은 역 문서의 `{{駅情報}}`를 사업자별로 읽어 씁니다(`tools/wiki_station.py`). 같은 이름의 다른 역은 사업자, 노선, 도도부현으로 가려냅니다. Wikidata는 역 문서가 없을 때만 쓰고, 같은 노선을 지나는 항목만 받습니다. Wikidata 날짜에는 이설일, 다른 사업자의 개업일이 섞여 있습니다.
- 3섹 이관은 역 이름을 대응표(`RENAME`)로 맞춘 뒤 판정하고, 공유 역의 km 간격이 어긋나면 이름만 같은 다른 역으로 봅니다.
- 환승 묶음: 같은 이름은 350m 안, 이름이 다른 역은 역 문서의 `乗換`·`接続路線` 칸에 적힌 것만 잇습니다. 같은 노선의 이웃 역은 묶지 않고 묶음 지름은 1.1km까지입니다. 문서가 없는 역끼리는 150m 안이면 묶습니다.
- 끝에서 이어짐: 위키 노선도의 분기가 끝 역에 닿거나, 양쪽 다 그 역에서 끝나면서 JR·노면전차이거나 노선 문서가 직통을 적은 경우입니다. 다른 사업자 사이는 양쪽 문서가 서로를 직통으로 적어야 합니다. 예외는 `gen_wiki.py`의 `NOCONT`입니다.
- 현행 역 좌표는 N02 2024판 역 점과 이름·사업자로 대조합니다. 600m 넘게 어긋나거나 좌표가 없으면 N02 값을 씁니다.
- 대표 이름은 가장 늦은 시기의 표에서 가져오고, 옛 이름은 노선별 이름과 기간이 있는 이름으로 남깁니다.
- 원자료 노선과 짝지은 결과는 이름이 일치할 때만 한글 이름과 읽기에 씁니다. 이름이 다르면 `lines_ko.json`, `lines_kana.json`의 값을 씁니다.

## 3. 시간축 규칙

### 3.1 완주율 3기준
| 기준 | 분모 | 분자 |
|---|---|---|
| **현행** (기본) | 오늘 영업 중인 `normal` 단위 | 그중 탄 것 |
| **역대** | `normal` 단위 전체. 폐선 포함, 분모 밖 구간 제외 | 그중 탄 것 |
| **특정 연도 Y** | Y년 중 **하루라도** 영업한 `normal` 단위 | 유효 날짜 범위가 Y년 말까지 끝나는 기록 중 해당 단위 (§2.8 J) |

"단위"는 "기록 승계" 설정에 따라 (lineage, edge) 또는 (carryover_group, edge)입니다 (§2.8 E). 승계 켬에서는 이관 구간이 한 번 들어갑니다. 승계 끔의 이관 구간, JR 예외 4곳, 사철 공동 영업은 단위별로 따로 들어갑니다. 분자는 언제나 분모 단위 안에서만 셉니다 (§2.8 O).

### 3.2 변화 유형별 처리
| 유형 | DB | 기록 처리 |
|---|---|---|
| **사업자 전환** | `transfer`. edge는 닫히지 않고 그대로 | **기본: 자동 승계**. 설정 "사업자 전환 시 기록 승계"를 끄면 국철·JR에서 타사로 넘어간 구간만 단위가 갈림 (§2.8 E) |
| **선로 이설** | `relocate` | 옛 선로 탑승은 **폐선 기록**, 새 선로는 **다시 타야** 현행 완주 |
| **부분 폐선** | 해당 edge만 `close`. 노선 ID 유지 | 폐지 구간 탑승은 역대 기준에만 반영 |
| **중간 구간 폐선** (노선이 둘로 끊김) | 위와 같음 + `checks/intentional_gap.yaml` | 노선은 하나, 진행률도 하나. 지도·노선도에서 끊어져 보임 |
| **연장 개업** | `open` | 기존 완주가 풀릴 수 있음 → 노선 변경 소식 알림 |
| **역 신설** | 지난 역은 `open_stop`만, 앞으로 생기는 역은 `new-station` 도구 (§2.10) | 신설 전 기록도 그 노드를 지나간 것이므로 나뉜 edge가 모두 채워짐 |
| **폐역** (선로는 그대로) | `close_stop`. edge는 그대로 | 그 역을 지나는 기록에 영향 없음 |
| **폐선 후 재개업** | 같은 노드·선로면 같은 edge에 `open` 재발생, 다르면 새 edge | 같은 edge면 옛 기록 인정, 새 edge면 다시 타야 함. 표시는 §2.9 |
| **재해 불통** | `suspend`. 정식 `close` 전까지 현행 분모에 포함 | 탑승 기록 불가 기간. **역 방문은 가능** |
| **BRT 전환** | 법적 폐지 전이라도 `close` + `reason: brt` (노리츠부시 규칙) | 폐선과 같이 처리 |

### 4.2 조사 결과 (2026-10-30, 직접 집계)
- **폐선 목록 자체가 공개 데이터마다 불완전**: station_database는 1970년대 폐선 50개, Wikidata는 34개이며 둘 다 노면전차망이 빠져 있음. 완전한 목록은 일본어 위키백과 「日本の廃止鉄道路線一覧」과 개별 문서에서 만들어야 함 (Phase 3).
- **정밀 선형**: OSM 폐선 선로 8,954개 way와 station_database 폐역 좌표를 대조한 결과, 역의 80% 이상이 선로 150m 이내에 있는 노선 비율은 1970년대 16/50 (32%), 1980년대 38/99 (38%), 2000년대 12/27 (44%). 2005년 이후 폐선은 국토수치정보 N02 연도별 판에 정밀 선형이 있어 별도로 확보됨.

### 4.5 열람 전용 등급 (`archive`)
왓카나이잔교역(稚内桟橋, 1938~1945)처럼 **위치와 km가 없어도 순서가 명확한 역·노선**을 노선 화면에 보여 줍니다. 표시 여부는 데이터 상태로, 기록 허용은 기준일로 판정합니다.

```yaml
# archive/jr-hokkaido/soya.yaml
line: l_soya
stops:
  - id: a_wakkanai_sanbashi
    route: r_soya_main
    after: n_wakkanai      # 이 역 다음 자리. 앞의 열람 전용 역 ID도 쓸 수 있음
    opened: 1938-XX-XX     # 모르면 null
    closed: 1945-XX-XX     # 모르면 null, 화면에는 ~?
    km: null               # 모르면 null, 화면에는 ?
    source: "wikipedia:<revid>"
lines:
  - id: a_shibetsu_kido
    at: n_shibetsu
    closed: 1959-XX-XX
    source: "wikipedia:<revid>"
```
이름은 다른 ID와 같이 `names/`에 두고 한글 이름 검사를 받습니다. 연속된 열람 전용 역은 `after`로 사슬을 만들고, 뒤에 생긴 역과의 순서는 `before`로 고정합니다.

| 항목 | 규칙 |
|---|---|
| 표시 | 폐역·폐선과 같은 3단계 흐림. 메인 설정과 기록 화면 맨 위의 체크박스로 끌 수 있음 (기본 켬) |
| 날짜 | 연도만 표시. 모르는 값은 DB에 NULL, 화면에 `~?`. km도 같음 |
| 선택 | 출발·도착역으로 고를 수 없음. 탭하면 폐지 연도와 안내만 표시 |
| 현행 끝 역 너머의 폐지 구간 | 줄기를 가늘고 흐리게 이어 그림 |
| 완주율·거리 | 모든 기준에서 제외. 분모가 바뀌지 않음 |
| 지도 | 그리지 않음 |
| 방문 | 역 방문 기록 불가. 파일을 통째로 지워도 통계가 같아야 하기 때문 |
| 승격 | 기준일 이후 폐지분은 역 목록·순서·영업km가 확정되면 `기록 가능`으로 올림. 기준일 이전 폐지분은 데이터가 갖춰져도 올리지 않음 (확정) |
| 제외 | 옛 노면전차망, 전용선·화물선, 미개업선 |

- `archive`는 `edges`·`km`·`events`를 건드리지 않습니다. 파일을 통째로 지워도 기록과 통계는 그대로입니다.
- km를 모르는 역은 선로망에 넣지 않는 원칙(§2.8)도 지켜집니다.
- 자료량 (측정 당시 경계는 1970년): 위키 노선도 표본 135개에서 1970년 이전 폐역이 연도까지 215개 (km까지 있는 것 152개). 위키 폐선 일람은 전체 시대 약 700항목 (노면전차 포함, 이관 노선 제외). station_database는 1970년 이전 폐선 47개.
- 세 노선 목업에서는 위키 노선도에 연도가 없는 행을 `~?`로 표시했습니다. 연도는 각 노선 문서에서 보강할 수 있습니다.

### 4.6 탑승 기록 허용 범위 (판정)
**수록 기준은 구간의 법적 폐지일입니다. 1969-12-08보다 이른 날짜는 입력해도 저장되지 않고 날짜 모름이 됩니다.**

| 구분 | 탑승 기록 | 역대 완주율 분모 |
|---|---|---|
| 현행 노선 | 허용 | 포함 |
| 국철·JR 폐선, 1969-12-08 이후 법적 폐지 | **허용** | 포함 |
| 사철 폐선, 2000년 이후 | 노선별 검증 후 허용 | 포함 |
| 사철 폐선, 1969-12-08~1999 | 노선별 검증 후 허용 | **제외** (`outside`). 세 기준 모두에서 빠지고 화면에 따로 표시하지 않음. 목록이 완성되면 분모로 옮기고 안내 |
| 기준일 이전 폐지 | 불가, 표시만 | 제외 |

**왜 이 경계인가**
| 후보 | 판단 |
|---|---|
| 1987 (JR 출범) | 탈락. 노리츠부시가 허용하는 국철 폐선 기록을 가져올 수 없고, 데이터상 넘어야 할 벽도 없음. 국철 폐지의 절정인 1980년대를 잘라냄 |
| 1970-01-01 | 幸袋線(1969-12-08) 기록을 가져올 수 없어 CSV 호환이 깨짐 |
| **1969-12-08** | 노리츠부시 국철 기록이 전부 들어오는 가장 늦은 날짜. 경계가 날짜 하나로 끝남 |
| 1960년대 이전 | 탈락. 사철 목록이 열려 있어 분모가 흔들림 |

**측정 근거 (2026-10-31, 로그인 세션 읽기 전용)**
| 항목 | 결과 |
|---|---|
| 노리츠부시 규칙 | 국철·JR은 "おおむね1970年以降", 사이트 개설 후 폐지는 전부, 자료가 충분하면 예외 수록 |
| 타임머신 국철 139개 (마지막 폐지일 연대) | 1960년대 2, 1970년대 14, 1980년대 90, 1990년대 9, 2000년대 3, 2010년대 12, 2020년대 9 |
| 가장 오래된 값 | 手宮線 1962-05-15 (여객 폐지, 법적 폐지는 1985-11-05), 幸袋線 1969-12-08 |
| 사철 | 2000년대 이후 중심. 가장 오래된 것은 熊本電気鉄道 菊池線 1986-02-16 |
| 탑승일 입력 | `type=date`, 최솟값 없음, `날짜 등록 안 함` 선택 가능. 서버 검증은 시험하지 않음 |
| 위키 노선도 확인 | 국철·JR 1970~1986 50/52, 1987~1999 39/41. 사철 1970~1986 45/56, 1987~1999 12/13 |
| 받은 문서의 km 90% 이상 | 국철·JR 1970~1986 10/13, 사철 1970~1986 12/14 (표본, 나머지는 지선·구문 문제가 섞임) |

- "사철"은 국철·JR이 아닌 모든 사업자입니다 (공영, 3섹, 모노레일, 신교통, 강삭 포함). 국철에서 이관된 뒤 폐지된 구간은 국철 시기의 단위가 있으므로 분모에 들어갑니다 (§2.8 O).
- 국철·JR은 노리츠부시 139개에 根北線 같은 추가분을 더한 목록으로 대조합니다. 사철은 1986년 이후 일부만 대조 상대가 있고 station_database 목록도 불완전합니다. 그래서 같은 기준일을 쓰되 분모만 다르게 둡니다.
- 根北線(1970-12-01)은 노리츠부시에 없지만 기준일 이후이므로 수록합니다.
- 手宮線처럼 여객 폐지와 법적 폐지가 다른 노선은 법적 폐지일로 범위를 판정하고, 역 선택기 판정은 기존대로 마지막 운행일을 씁니다.
- 폐지일이 범위 날짜일 때는 범위의 하한이 기준일 이상이어야 기록 가능입니다. 기준일에 걸치면(`1969-XX-XX`, `196X-XX-XX`) 열람 전용입니다.
- 특정 연도 완주율의 연도 선택은 1970년부터입니다. 그 이전은 분모를 만들 수 없습니다.
- **탑승일·방문일이 1969-12-08보다 이르면 자동으로 날짜 모름이 됩니다.** 입력칸이 바로 `날짜 모름`으로 바뀌어 알 수 있고, 기준일을 설명하는 문구는 화면에 쓰지 않습니다. 연도만 입력해도 같고, 연대는 1970년대부터 고릅니다.
- **폐선 구간에 폐지 이후 날짜를 넣어도 자동으로 날짜 모름이 됩니다.** 고른 구간이 그날 영업하지 않았으면 저장을 막지 않고 날짜 모름으로 저장합니다.
- CSV의 해당 행도 같습니다. 날짜 모름으로 들어오고 원문을 보존합니다.
- 노리츠부시 CSV의 사철 행은 검증된 노선이면 `outside`로 들어오고, 수록 전이면 `unknown_ref`로 보존됩니다.
- 다른 서비스: 鉄ログ는 폐선 미지원 (직접 확인), 그 밖의 앱은 체계적 수록 사례를 찾지 못함 (§4.4).

### 4.7 지도 위치 상태 (역·노선 공통)
| 대상 | 필드 | 값 |
|---|---|---|
| 역 | `positions/`의 `quality` | `precise` 선로와 맞는 정밀 좌표, `approx` 대략적인 좌표, `none` 없음. `none`도 비워 두지 않고 적고 `checked`에 확인일을 남김 |
| 구간 | `edge.geometry_quality` | `precise` / `none` |
| 노선 | `route.map_coverage` | `full` / `partial` / `none`. 빌드 시 구간에서 계산 |

"아직 조사하지 않음"과 "조사했지만 없음"이 구분되므로, 위치를 찾아야 할 역 목록을 바로 뽑을 수 있습니다. `approx` 좌표는 지도에 점을 찍지 않고 위치 미확인 표식의 방향(§7.3)에만 씁니다.

## 5. 사용자 기록

### 5.1 구간 탑승
노선 + 출발역 + 도착역 + 날짜 (시간·열차명·편성·메모 선택). 저장은 "노선 + 역 경로 + 날짜". **날짜 미상 허용** (노리츠부시 CSV의 `0000-00-00`처럼 날짜 없이 기록된 경우).

### 5.2 역 방문 (★ 신규)
- 열차로 구간을 타지 않고 역만 방문한 경우를 기록 (예: 현재 열차로 갈 수 없는 츠가루선 민마야역에 차로 방문)
- **별도 기록 공간**: "기록" 탭 안에 **구간 탑승 / 역 방문** 두 목록
- **완주율·거리에는 영향 없음, 지도에는 영향 있음** (점이 칠해짐)
- 폐역 방문도 가능 (폐역 터 답사). 열람 전용 역은 방문 기록을 남기지 않습니다 (§4.5)
- 통계: 방문 역 수(현행 / 폐역), 도도부현별 방문 역 수 — 완주율과 별도 지표

### 5.3 지도 위 점의 상태 (확정)
| 상태 | 조건 | 표시 |
|---|---|---|
| 미방문 | 기록 없음 | 회색 테두리, 가운데 흰색 |
| **통과** | 탄 구간의 중간역 | 파란 테두리, **가운데 뚫린 원** |
| **발로 밟음** | 승하차역, 또는 역 방문 기록 | **파란색으로 꽉 찬 원** |

폐역은 파랑 대신 **빨강**. 역 방문만 있고 구간 탑승이 없으면 점만 칠해지고 선은 회색 그대로.

### 5.4 불확실한 날짜
마스터 데이터(개업·폐지일)와 사용자 기록(탑승일·방문일) 모두 **같은 날짜 형식**을 씁니다. 아래의 "화면 표기"는 마스터 날짜의 규칙입니다. 탑승일·방문일의 원본은 입력값 `date_input`이고, 화면에는 계산된 날짜를 입력 형식 그대로 보여 줍니다. 날짜 모름이 된 기록은 `날짜 모름`으로 보이고, 입력값은 수정 화면에서 볼 수 있습니다.

| 아는 정도 | 저장 (ISO 8601-2 / EDTF) | 화면 표기 | 계산용 범위 |
|---|---|---|---|
| 일까지 | `1972-06-19` | `~1972` | 그날 하루 |
| 월까지 | `1972-02-XX` | `~1972` | 1972-02-01 ~ 02-29 |
| 연도까지 | `1970-XX-XX` | `~1970` | 1970-01-01 ~ 12-31 |
| 연대까지 | `197X-XX-XX` | `~197?` | 1970-01-01 ~ 1979-12-31 |
| 모름 | **NULL** | `~?` | 개업일이면 하한 없음, 폐지일이면 수록 범위 전체 |
| 끝나지 않음 | **`ongoing`** | 표기 없음 | 오늘 너머까지 |

- **모르는 값은 NULL, 끝나지 않은 기간은 `ongoing`입니다.** 두 뜻을 한 값에 섞지 않습니다. 빈 문자열, 0, 임의의 대표값도 넣지 않습니다. 날짜·km·연도 모두 같고, 화면에서만 `?`로 보입니다.
- **마스터 날짜는 화면에 연도만 표시합니다.** 월·일은 DB에만 저장하고 판정에만 씁니다. 표기가 짧아지고, 불확실한 날짜도 같은 모양으로 보입니다.
- 모든 날짜는 빌드 시 **(가장 이른 날, 가장 늦은 날)** 범위로 변환해 저장 → 계산은 범위로만 함. 원본 표기는 EDTF로 통일합니다 (`1894`가 아니라 `1894-XX-XX`). `ongoing`은 lo/hi에서 최댓값입니다.

**범위로 판정하는 규칙**
| 판정 | 규칙 |
|---|---|
| 역 선택기에서 선택 가능 여부 | 탑승일 범위가 역의 존재 범위와 **겹치면 선택 가능**. 확실히 겹치지 않을 때만 회색 |
| 애매한 경우 | 선택은 되지만 날짜 칩에 `?` 표시 + 저장 시 "이 날짜에 영업했는지 확인되지 않았어요" 안내 (막지 않음) |
| 특정 연도 완주율 | Y년 중 **확실히 영업한** edge만 분모에. 애매한 edge는 분모·분자 모두에서 빼고 "판정 불가 n구간"으로 따로 표시. 폐지 연도만 아는 구간은 폐지 해에 영업한 것으로 침 (1월 1일 폐지 가능성 하나로 빼지 않음) |
| 현행·역대 완주율 | 날짜 불확실성과 무관 (지금 영업 중인지 / 등급이 `normal`인지만 봄) |
| 탑승일 미상·부분 기록 | **유효 날짜 범위**를 계산해 그 끝이 Y년 말 이전이면 Y년 완주율에 포함 (§2.8 J). 완전히 버리지 않음 |
| 수록 범위 판정 | 기준일 이후 폐지 근거가 있으면 등급 판정. 근거가 없고 순서가 명확하면 열람 전용. 순서도 불명이면 `staging/` |
| CI 위상 검사 | 날짜가 범위이므로 범위의 양 끝 시점에서 각각 검사 |

개업은 `1987~`, 폐지는 `~1987`로 적습니다.

## 7. 지도 표시 사양

**운행 구간은 지도에서 끊기지 않습니다.** 운행 중인 구간이 지도에서 끊겨 보이면 데이터 결함입니다 (사용자 지시, 2026-11-02). 선형은 올바른 선로를 따라야 하고, 역 위치는 그 선 위에 있어야 합니다. `tools/check_geometry.py`가 모든 현행 구간을 검사합니다. 위치 미확인 표식(§7.3)은 폐지 구간에만 쓰고 현행 구간의 공백을 가리는 데 쓰지 않습니다.

### 7.2 레이어와 줌

역 점은 그 역의 선 위에 그립니다. 역 좌표와 선로는 다른 자료라 그대로 그리면 점이 선에서 떨어지고 끝 역이 선 끝과 어긋납니다. `gen_tiles.py`가 선 위로 옮긴 값을 타일에 넣고, 원래 좌표(`node_position`)는 바꾸지 않습니다. 환승역은 노선마다 역 좌표를 그 노선 위로 옮긴 뒤 다른 점들과의 거리 합이 가장 작은 점을 씁니다. 평균은 선 사이 빈 곳에 뜨고, 가장 가까운 선 하나는 큰 역에서 한쪽으로 쏠립니다. 현행 선이 있는 역은 현행 선만 씁니다. OSM 선만 지나는 역은 OSM 선에 맞춘 점을 `rail-osm.pmtiles`에 두고, `rail.pmtiles`에는 넣지 않습니다.
MapLibre의 512px 타일 기준입니다. 360dp 폭에서 일본 전체는 z4 안팎, 도쿄권은 z8.5 안팎, 역 사이 1.5km가 25dp쯤 벌어지는 곳이 z10입니다. 시작 화면은 일본 전체, 범위는 z3.5~17.5입니다.

### 7.3 위치 미확인 폐지 구간의 지도 표현
삿쇼선처럼 현행 구간은 확실하지만 오래전 폐지된 일부 구간의 정밀 위치가 없는 경우(= "기록 가능" 등급 구간)입니다.

**원칙: 모르는 위치에 선을 그리지 않는다. 대신 "여기서 무언가 이어졌었다"는 표식만 남긴다.**

| 요소 | 표현 |
|---|---|
| **끊김 표식** | 위치 미확인 구간과 맞닿은 마지막 확인 역에서, 폐지 구간 방향으로 **짧게 사라지는 점선 꼬리**(화면상 약 16px). 방향은 다음 역의 대략 좌표가 있으면 그쪽, 없으면 선로의 마지막 진행 방향 |
| 색 | 미승이면 흐린 회색, 그 구간을 탄 기록이 있으면 **빨강** |
| 탭 | 하단 시트: `이 역 너머 폐지 구간 · 신토츠카와–이시카리누마타 · 34.9km · ~1972 폐지 · 정밀 위치 미확인 · 내 탑승 기록 1건` + "구간 보기" (노선 상세로 이동) |
| 노선 전체가 위치 미확인 | 지도에는 아무것도 그리지 않음. 노선 목록·검색·통계에는 정상 표시하고 "지도 미표시" 배지 |
| 역 방문 기록이 있는 위치 미확인 폐역 | 지도에 점을 찍지 않음. 기록 목록에서만 보임 |

**나중에 고려할 선택지 (기본 꺼짐)**: 역의 대략 좌표가 있는 경우 역과 역을 잇는 "개략선"(가는 점선, 매우 흐리게)을 설정으로 켜는 기능. 정밀 데이터와 섞여 보이지 않도록 선 모양을 확실히 다르게.

## 8. 기록 입력 화면 (역 선택기)

### 8.0 기록 탭
찾아서 고르는 길과 훑어서 고르는 길을 나란히 둡니다 (사용자 제안, 노리츠부시의 목록 방식). (+) 버튼은 검색이고, 탭 맨 위에서 `노선별`과 `탑승 기록`을 고릅니다.

| 단계 | 내용 |
|---|---|
| 현행 / 폐선 | 첫 갈래. **폐선은 노선이 아니라 구간으로 판정합니다.** 일부만 폐지된 노선은 폐선 쪽에 그 구간만 나옵니다 |
| 분류 | §2.5의 8분류, 정해진 순서. 구간이 없는 분류는 나오지 않음 |
| 회사 | 팩의 순서. 폐선의 국철은 JR 분류 안의 한 회사 |
| 노선 | 고르면 역 선택기. 저장하면 이 목록으로 돌아와 이어서 기록함 |

- 모든 줄은 한 버튼이고, 이름과 완주율, 그 아래 진행률 막대, 탄 km / 전체 km를 보여 줍니다.
- 현행은 오늘의 소속으로 묶습니다. 두 회사가 나눠 가진 노선은 회사마다 자기 구간만 나옵니다.
- 폐선은 구간마다 마지막 소유자 한 곳에만 넣습니다. 그래서 현행과 폐선을 합치면 역대 분모와 정확히 같습니다.
- 폐선 목록에서 연 노선의 기본 탑승일은 날짜 모름입니다. 오늘이면 그 구간을 고를 수 없기 때문입니다.
- 일부 폐지 노선의 줄에 어느 구간인지 표시하는 일이 남았습니다 (`closed_section`).
- 맨 위는 `노선`·`탑승 기록` 밑줄 탭이고, 현행/폐선은 요약 카드 안의 전환 단추입니다. 요약 카드의 큰 값은 %가 아니라 km입니다.
- 노선 줄의 막대는 **위치 띠**입니다. 노선을 실제 길이로 펴서 탄 자리에 칠합니다. 본선 다음에 지선을 잇고, 같은 구간은 한 번만 놓습니다. 필터는 전체, 타는 중, 안 탄 노선, 완주입니다.

**글꼴**
- 앱 글자는 Pretendard 1.3.9를 앱에 넣어 씁니다. Regular, Medium, Bold 세 벌만 넣습니다. 기기마다 글자 모양이 달라지지 않게 하려는 것입니다.
- 일본어 한자와 가나는 이 글꼴에 없어 기기 글꼴로 내려갑니다. 승차권 도장처럼 일본어로 읽혀야 하는 글자에는 `locale: ja`를 붙입니다.
- 가변 글꼴은 파일이 6.7MB이고 쓰지도 않을 굵기까지 들어 있어 쓰지 않습니다. 세 벌은 APK에서 3.3MB, iOS에서 4.7MB입니다.
- 라이선스는 SIL OFL 1.1이고 앱과 함께 배포합니다. 설정의 오픈소스 라이선스에서 볼 수 있습니다.

**표기 규칙**
- 완주율은 내림입니다. 탄 구간이 있으면 0%로 보이지 않게 소수를 늘립니다 (`0.02%`, 더 작으면 `<0.01%`). 안 탔으면 `0%`, 다 탔을 때만 `100%`입니다.
- 진행률 막대는 탄 구간이 있으면 최소 5dp입니다.
- km는 천 단위 쉼표를 쓰고 분자와 분모 모두 소수 한 자리까지 적습니다. 다 탔으면 두 값이 같게 보여야 합니다.
- 날짜는 `2026.11.2`, `2026.11`, `2026`, `1980년대`로 보여 줍니다. 영어는 `Nov 2, 2026`, `Nov 2026`입니다.
- 글자색은 먹색이고 파랑은 막대와 선에만 씁니다. 동작을 알리는 되돌리기와 출발·도착 글자만 예외입니다.
- 도도부현의 한국어 이름은 나무위키 문서 제목을 따릅니다(치바, 가나가와, 카가와). 역과 노선도 같습니다.

**저장 확인**: 작은 안내 대신 승차권 한 장이 화면 위에서 내려와 5초 동안 머뭅니다. 위로 밀면 바로 닫힙니다. 화면을 막지 않습니다. 구간, 날짜, 오른 완주율, 되돌리기가 있고 도장은 `乗車`, 그 노선을 다 타면 `完乗`입니다.

**통계**: 완주율, 숫자 카드(탄 노선, 완주, 지나간 역, 탄 회사), 곧 완주(남은 거리가 짧은 노선), 도도부현 타일 지도(47칸, 한 색의 진하기), 사업자, 노선 순서입니다.

### 8.0.1 역 선택기

세로 노선도 한 줄에서 두 번 탭하는 방식. 1차 목업 확인 완료, 이후 화면별로 확인받으며 다듬음.

| 요소 | 사양 |
|---|---|
| 상단 표시 설정 | 화면 맨 위에 체크박스 2개: `폐역·폐선 표시`, `열람 전용 역·노선 포함`. 앱 설정의 값을 그대로 쓰고, 여기서 바꾸면 바로 반영. 폐역·폐선을 끄면 열람 전용 체크박스는 비활성 |
| 선택 | 첫 탭 = 출발역, 두 번째 탭 = 도착역, 범위가 파랗게 칠해짐. 같은 역을 다시 탭하면 해제(순환에서는 `해제 / 한 바퀴` 선택), 범위가 있을 때 다른 역을 탭하면 처음부터. 상태는 `(route_id, seq)` |
| 탑승일 | 맨 위. 기본값은 현행 노선이면 오늘, 폐선이면 `날짜 모름`. 날짜를 바꾸면 아래 상태표를 즉시 다시 적용. 1969-12-08보다 이른 날짜와 고른 구간의 폐지 이후 날짜는 자동으로 날짜 모름이 됨 (§4.6) |
| 역 찾기 | 검색과 스크롤 인덱스. 도카이도 본선은 도쿄→오사카 두 탭 사이가 약 9,000dp |
| 지선·병행 경로 | 상단에 계통 전환 칩 (`본선 · 오누마~모리`). 본선 외에는 양 끝 역 이름. 같은 노선 안에서 칩을 바꿔도 출발역 유지 (§2.8 F) |
| 운전 계통으로 입력 | 노선 검색에 운전 계통도 함께 나옴 (`츄오 쾌속선 도쿄–다카오`). 고르면 한 줄 노선도로 입력하고, 하단 요약에 **공식 노선별 분해 결과**(`도호쿠 본선 1.3km · 츄오 본선 8.3km · 야마노테선 0.7km …`)를 보여 준 뒤 저장 |
| 분기 줄 탭 | 그 노선의 기록 화면으로 이동하고 그 역으로 스크롤. 고른 역이 있으면 먼저 `넘어가면 고른 역이 지워진다`는 팝업을 띄우고, 없으면 바로 넘어감. 기록은 노선마다 따로이고 한 기록으로 묶지 않음 (사용자 결정, 2026-11-03). 뒤로 가기는 직전 노선으로 돌아가고, 넘어온 만큼 거슬러 올라간 뒤에야 화면을 닫음. 돌아갈 때 고른 역이 있으면 같은 팝업을 띄움. 탑승일은 넘어가도 유지 |
| 환승 줄 탭 | 그 역을 고르는 것과 같음 |
| 신호장·분기점·화물역 | 표시하지 않음 (§2.4) |
| 고른 역 표시 | 고른 양 끝 역에 `출발`, `도착` 표시 (10-30 승인 목업) |
| 스크롤 인덱스 | 줄기 오른쪽의 손잡이를 끌어 이동. 30줄이 넘으면 항상 보임 |
| 그날 없던 역 탭 | 고르지 않고 "그 날짜에는 영업하지 않던 역이에요"처럼 이유를 안내 (10-30 승인 목업) |
| 역 3상태 | 탄 구간의 양 끝은 꽉 찬 원, 지나간 역은 가운데가 뚫린 원, 안 탄 역은 기본 (10-31 승인 목업). 지도 점의 §5.3과 같은 판정 |
| 하단 | 선택 요약 + `취소`와 `기록하기`. 역 수는 선택 가능한 역만 셈 |
| 빈 화면 | 고를 역이 없으면 이유를 한 줄로 안내 |

**탑승일 상태표**: 역·구간·분기·환승을 모두 고른 날짜의 상태로 그립니다. 그날 상태는 선로가 아니라 **같은 lineage의 멤버십이 그날 있는가**로 판정합니다. 시나노 철도선 화면에서 1990년을 고르면 영업 중이고 저장은 신에츠 본선으로 됩니다. 철수한 산요의 고베고속선 구간은 2020년에 이미 폐지입니다. 위계 단계는 §8.1입니다.
| 그날 상태 | 선·글자 | 선택 | 체크박스를 끄면 |
|---|---|---|---|
| 영업 중 (오늘은 폐지여도) | 1단계, `~연도` 표기 | 가능 | 그대로 |
| 날짜 모름이거나 범위가 겹침 | 1단계 + 날짜 칩 `?` | 가능, 저장 시 "이 날짜에 영업했는지 확인되지 않았어요" 안내 | 그대로 |
| 이미 폐지 | 3단계, `~2017` | 불가 | 숨김 |
| 개업 전 | 3단계, `2016~` | 불가 | 숨김 |
| 영업 중단 | 3단계, `운휴` | 불가 | 그대로 |
| 열람 전용 | 3단계 | 불가, 탭하면 폐지 연도와 안내 (§4.5) | 숨김 |

- 날짜를 모르면 그 노선에 존재했던 역을 모두 고를 수 있습니다. 열람 전용은 제외합니다.
- 통째로 폐지된 구간은 경계에 점선 구분선, 그 바로 아래 `~2020 폐지`. 폐지 단계마다 구분선과 날짜를 두고, 폐지 구간 안에서 더 일찍 폐역된 역은 그 역에만 날짜 칩을 둡니다.
- 위치 미확인 구간은 구분선 옆에 작은 "지도 미표시" 아이콘 (기록은 정상적으로 가능).
- 날짜가 불확실한 폐역·폐지 구간은 아는 만큼만 표기합니다 (`~1970`, `~197?`, `~?`). 판정 규칙은 §5.4.
- 화면 제목과 표시 km도 고른 날짜를 따릅니다 (1985년이면 후타마타선).

**순환 입력** (`route.closed` 또는 `service.closed`로 판정)
- 세로 목록은 공식 순서로 한 줄로 그리고, 끝에 `○○로 돌아옴`을 둡니다.
- 두 번째 탭 뒤 두 방향의 km를 보여 주는 토글을 띄웁니다. 기본은 짧은 쪽이고, 칠하기는 목록 끝을 넘어 이어집니다.
- 시작역의 맨 위 행과 맨 아래 행을 고르면 한 바퀴입니다. 다른 역에서 시작한 일주는 같은 역을 다시 탭해 `한 바퀴`를 고릅니다. 두 바퀴 이상은 저장 화면의 횟수로 받습니다.
- 올가미의 두 번째 행은 캡션을 생략하고 `도초마에로 돌아옴`만 둡니다.

### 8.1 환승·분기 표시 (★ 고유 기능)
기록 중인 노선 곁에 갈아탈 수 있는 노선과 갈라지는 노선을 함께 그립니다. **이 절이 유일한 규범입니다.** 지난 안과 측정값은 부록 A에 있습니다.

| 단계 | 대상 | 표현 |
|---|---|---|
| 1 | 기록 중인 노선, 현행 역 | 가장 진하고 굵게 |
| 2 | 현행 분기·환승 노선 | 흐린 회색. 폐선과 확실히 구분될 만큼은 진하게 |
| 3 | 폐선 분기, 폐역 | 훨씬 더 흐리게. 노드와 글자, km 모두 |

표시하지 않는 것: 교각, 터널, 통과만 하는 교차 노선, 강, 바다, 신호장·분기점·화물역. 구간이 파랗게 칠해져도 분기·환승 선의 색은 그대로입니다.

**승인 시안**: 역 선택기는 [목업 원본](mockups/station-selector.tpl.html), 앱 화면은 [Figma 시안 9장](https://www.figma.com/design/VeoTJVzelQ8Kzl7kjJmbgw)입니다. Figma의 역 선택기는 §8.1이 빠진 단순판이며, 이 절이 우선합니다. 화면은 구현 뒤 시안과 나란히 놓고 확인합니다 ([추적표 규칙](spec-trace/README.md)).

**화면 배치: 위키식 줄 배치 (확정)**

치수는 목업에서 옮긴 값입니다 (단위 dp). 줄기 x 66, 환승 점 간격 18, 분기 줄기 x 82, 분기 끝 원 x 99 반지름 5, 글자 x 114, 곡선 반지름 6, 캡슐 높이 26. 역 원 반지름은 현행 8.5, 폐역 4.5, 고른 양 끝은 반지름 13의 링을 더합니다. 줄기 굵기는 영업 7, 폐지 4입니다 (목업 9와 5에서 앱 시안에 맞춰 줄임). 색은 §7.1 토큰이고, 1단계는 글자색, 2단계는 현행·미승, 3단계는 폐선·미승입니다. 한자 이름은 한글 옆에 작게 적습니다.
- 왼쪽 좁은 그림 열에 기록 중인 노선과 가지를 그리고, 글자는 오른쪽 한 열에 모음
- 환승은 줄기 왼쪽 캡슐의 점, 분기는 줄기 오른쪽 둥근 곡선(4분의 1 원)
- 분기는 역 위아래의 독립된 줄. 가지마다 노선명 + `다음 역 › 끝 역`, 줄 전체가 탭 영역
- **영업km는 자료가 있는 한 항상 표시** (역 줄 오른쪽 끝)
- **기본은 펼친 상태**. 설정의 `분기선 표시`를 끄면 곡선과 분기 줄을 숨기고 그 노선을 캡슐로 보여 줌
- **행 높이는 역·가지 모두 최소 48dp.** 지금 목업은 46/32/29라 전부 미달입니다. 행 높이는 글자 크기의 함수로 둡니다. 선택할 수 없는 폐역 행만 더 낮출 수 있습니다. 전체 높이는 대체로 8~14% 늘고, 폐역이 많은 소야 본선은 폐역 행을 낮춰 약 10%입니다

**요소별 규칙**
| 요소 | 사양 |
|---|---|
| 환승 | 역 원을 왼쪽으로 늘린 캡슐로 감쌈. 타 회사 노선과 폐선도 표시. 노선 이름은 역 이름 아래에 모아 적음 |
| 환승 번호 | 세로선 모양이 같은 노선을 점 하나로 묶음. 묶음은 지나감·위로 끝남·아래로 끝남 세 가지라 **점은 보통 최대 3개**이고, 방향을 모르는 `unknown` 묶음이 있으면 넷째 점이 됩니다 (팩에 2곳). 묶음이 둘 이상이면 왼쪽부터 ①②③을 붙이고, 역 아래 목록도 같은 번호로 나눔. 폐선·현행이 섞인 묶음은 현행색 |

| 환승 노선의 흐름 | 그 역을 지나는 노선은 점 위아래로 짧은 세로선, 그 역에서 끝나는 노선(시발 포함)은 들어오는 쪽으로만. 방향은 위키에서 노선 이름이 적힌 쪽, 없으면 다음 역 좌표 (세 노선 끝나는 노선 78건: 위키 51, 좌표 27). 둘 다 없으면 `flow=unknown`이고 세로선 없는 점 |
| 다른 이름 역 | `산요 전철 본선(산요히메지)`처럼 괄호로. 같은 역의 같은 회사 노선은 `한큐 고베 본선·타카라즈카 본선(오사카우메다)`로 묶음. 승계 표기와 겹치면 `텐류하마나코 철도(신카케가와) 1987~` |

| 긴 목록 | 접지 않고 전부 펼칩니다. 사용자가 사진으로 승인한 형태입니다 (10-31). 전국 최대는 나고야의 약 10개 (거리 근사) |
| 분기 | 오른쪽 둥근 곡선. `side`에 따라 역 위쪽 또는 아래쪽 줄에 놓음. `다음 역 › 끝 역`, 다음 역이 끝 역이면 하나만. 같은 역에 여럿이면 줄을 쌓음. 다른 이름 역은 분기 줄에도 괄호 표기 |
| 끝에서 이어짐 | 줄기 끝의 짧은 점선 + 노선 이름. 기준은 **마지막 현행 역**이라 뒤에 폐지 구간이나 열람 전용 역이 있어도 유지. 여러 노선이면 여러 줄. 상대 노선이 그 역을 지나가면 두 방면을 적음 (`하코다테 본선 오타루·이와미자와 방면`) |

| 탑승일 연동 | 고른 날짜의 상태표(§8)를 따름. 그날 없던 노선은 체크박스를 따름 |

### 8.2 빠른 수정과 일괄 삭제 (★)
테츠로그는 일괄 삭제가 없어 시험 기록 18개 역을 지우는 데 역마다 3번씩 눌러야 했습니다. noriori는 다른 화면으로 들어가지 않고 **그 자리에서 바로** 고칩니다.

| 동작 | 사양 |
|---|---|
| 구간 탭 | 노선 상세의 세로 노선도에서 구간을 누르면 즉시 탑승 ↔ 미승 전환. 끌 때 그 구간을 덮는 기록이 여럿이면 전부에 적용하고 영향 건수를 표시. 덮는 기록은 화면의 집계 단위 기준. 끄기는 표시 역 경계에서만 되고, 숨은 노드에서 끊어야 하는 구간은 안내만 함 |
| 역 탭 | 역 노드를 누르면 즉시 방문 ↔ 미방문 전환 (§5.2). 역 방문 기록만 바꿈. 승하차로 칠해진 역은 기록을 고쳐야 꺼짐 |
| 범위 지정 | 길게 누른 뒤 끌어서 여러 구간을 한 번에 전환 |
| 되돌리기 | 모든 변경 후 화면 아래에 5초간 "되돌리기" 표시. 확인 팝업은 띄우지 않음 |
| 기록 단위 삭제 | 기록(ride)은 한 덩어리이므로 한 번에 삭제. 기록 목록에서 여러 개 선택 삭제 가능 |
| 범위별 일괄 삭제 | 여정 전체, 노선 전체, 가져온 파일 전체를 한 번에 삭제 (되돌리기 가능) |

**데이터 처리** (구조는 ARCHITECTURE §3.4)
- 구간을 탭해 켤 때 되살릴 조각이 없으면 그 구간만 있는 날짜 없는 기록이 만들어짐. 나중에 날짜를 넣을 수 있음. 끝은 승하차가 아니라 통과로 침 (§2.8 M)
- 기록의 구간을 끄면 **기록에서 그 구간을 잘라 냄** (`소엔→토베츠`에서 `A→B`를 끄면 `소엔→A`, `B→토베츠` 두 기록). 새 ID 외에는 날짜, 메모, 여정, 열차명, 차번, 가져온 출처, 만든 날이 양쪽에 그대로. 남는 구간이 없으면 삭제 표시
- 끈 뒤 5초 안에는 되돌리기로 원래대로 돌아감. 끈 구간은 삭제 표시 조각으로 남아 그 뒤에도 날짜째 되살릴 수 있고, 같은 구간을 다시 켜면 그 조각이 살아남
- 삭제는 삭제 표시라서 복원할 수 있음. 설정의 `삭제한 기록`에서 되살림
- 일괄 전환은 전부 되거나 하나도 안 됨. 덮는 기록 중 하나라도 숨은 노드에서 끊어야 하면 아무것도 고치지 않고 안내함
- 노선 상세의 진입점: 역 선택기 제목의 정보 버튼, 지도 노선 시트의 정보 버튼, 통계의 노선 줄. 기존의 `노선을 누르면 역 선택기`는 유지

## 9. 이름 표기

### 9.1 영어
① 사업자 공식 영문 표기 ② Wikidata 영어 라벨 ③ 일본어 히라가나 읽기의 헵번식 자동 변환(장음 기호 없이). 히라가나 읽기가 있으면 고유명사는 1:1로 옮길 수 있습니다 (사용자 지시, 2026-11-02).

노선은 `線` → `Line`, `本線` → `Main Line`, `支線` → `Branch Line`, `新幹線` → `Shinkansen`, `鉄道` → `Railway`로 옮기고 나머지는 읽기대로 적습니다. 노리츠부시 읽기 앞에 붙은 회사 이름은 일본어 이름에 없는 글자이므로 뗍니다. `ん`은 b, p, m 앞에서 `m`, 모음 앞에서 `n'`입니다. 계통은 양 끝 역의 영어 이름을 `~`로 잇습니다. 만드는 도구는 `tools/gen_en_names.py`이고 결과는 `data/source/names/en.yaml`입니다. 앱 문구는 영어로 번역합니다.

일반명사만 남아 서로 다른 노선이 같은 이름이 되면 일본어에 없어도 회사 약칭을 붙입니다 (`Keikyu Main Line`, `Keisei Main Line`). 역 이름의 숫자 `丁目`은 `4-chome`처럼 적되, 공식 표기가 다른 도쿄 지하철과 도덴은 그 표기를 따릅니다 (`Aoyama-itchome`). 고친 값과 이유는 `data/overrides/en_fix.json`에 있습니다.

### 9.1.1 일본어
고유명사는 일본어 원문입니다. 앱 문구는 노리츠부시와 일본어 위키백과의 표현을 따릅니다: 完乗, 未乗, 乗車, 廃線, 廃駅, 運休, 乗換, 営業キロ, 事業者, 運転系統, 大手私鉄, 準大手私鉄, 鋼索線.

### 9.2 한국어
**나무위키에 문서가 있으면 그 제목을 그대로 씁니다 (확정).** 표기가 규칙과 달라도 고치지 않습니다. 한국어 사용자가 검색하는 이름과 같고, 표기 논쟁이 사라지며, 기여자가 판단할 일이 줄어듭니다. 대신 앱 안에서 `유라쿠초`와 `하마마츠쵸`가 공존하는 것은 받아들입니다. 규칙은 나무위키에 없는 이름에만 씁니다.

| 순위 | 출처 | 방법 |
|---|---|---|
| 1 | **나무위키** | 공개 덤프로 일본어 역명과 짝짓고, 규칙과 다르거나 없는 역은 실제 문서로 최종 제목 확인. 문서에 일본어 역명이 있어야 인정 |
| 2 | 일본어 위키백과 | 역의 읽기와 존재 확인. 나무위키에 없거나 읽기가 어긋날 때 이 읽기를 기준으로 삼음. 위키데이터 한국어 라벨은 대조용 |
| 3 | 국립국어원 표기 + noriori 규칙 | 국립국어원 + つ→츠 + 어두 거센소리 + 굳은 지명 + 가타카나 사전. 위 두 곳에 표기가 없는 이름 |

- 이름마다 `source`(`namuwiki`/`rule`/`hand`)와 확인일을 남깁니다. 일본어 위키백과는 읽기를 확인한 근거로 `reading_source`에 적습니다.
- **첫 출시 전에 한 번 수집해 제목을 고정합니다.** 매년 전체를 다시 수집하지 않고, 이후에는 신역과 사용자 제보만 문서 하나씩 확인합니다. 제목을 고칠 때 옛 제목은 검색용 별칭으로 남깁니다.
- 읽기가 어긋나면 나무위키 제목을 쓰지 않습니다. 같은 한자의 다른 역일 수 있습니다. **같은 한자에 읽기가 다른 역이 한 제목을 나눠 쓰는 것도 금지합니다** (CI 검사). 규칙과 다른 값은 음절 수와 무관하게 사람 확인으로 보냅니다.
- 수집 도구는 일시 오류와 문서 없음을 구분하고, 식별 가능한 User-Agent로 저속 접근합니다. 지금까지의 프로토타입 수집은 브라우저 User-Agent를 썼습니다. 본수집 전에 바꿉니다.

## 10. CSV 가져오기·내보내기

**양방향으로 모두 지원합니다.** 노리츠부시에는 올리기 기능이 없습니다 (2026-10-31, 로그인 세션의 기록 조회·마이페이지·기록 등록 화면과 공개 안내 확인. 파일 입력칸과 가져오기 링크 없음, CSV 내려받기 링크 4개뿐). 그래서 우리 CSV를 노리츠부시로 되돌릴 수는 없고, 호환의 목적은 익숙한 형식, 기존 스프레드시트·스크립트 재사용, 나중에 그쪽이 가져오기를 열 경우 대비입니다.

**다운로드 위치**: 메인 메뉴 "登録した記録を編集する → 全鉄道" (`/common/summary_sp.php`) 화면 하단

| 항목 | 내용 |
|---|---|
| 인코딩 · 줄바꿈 | **Shift_JIS (CP932)**, LF |
| 헤더 (일반판) | `会社名,路線名,乗車開始駅,乗車終了駅,乗車キロ,乗車日` |

### 10.2 가져오기 설계
- 인코딩 자동 판별 (CP932 / UTF-8), 헤더로 일반판·코멘트판·noriori 전체판 구분
- noriori 전체판은 없는 `ride_id`만 추가. 같은 ID는 건너뜀 (수정 내용의 복원은 JSON이 맡음). ID 열이 있으면 이름 매칭을 하지 않음
- 호환판의 고정 ID(UUIDv5) 입력은 정규화한 원문 5열 + 같은 파일 안의 동일 행 순번. 가져오기는 없는 행만 넣음
- (노선, 출발, 도착, 날짜)가 같은 기존 기록은 중복 후보로 확인 화면에 띄움. 삭제했던 ID는 "삭제했던 기록"으로 표시
- `0000-00-00` → 날짜 미상 (NULL), 코멘트 → 기록 메모
- **노선명 별칭 표** (`names/aliases-noritsubushi.yaml`, 앱에는 `names.sqlite`로 포함): `노선명 (괄호)` → noriori의 (노선, 계통). ①지선은 계통으로, ②쪼갠 부분은 그 노선의 계통으로(noriori도 집계하는 구간만 계통에 넣으므로 1:1 대응), ③애칭은 노선으로. 대괄호로 적힌 분기점(`[枇杷島分岐点]`)은 숨은 노드로 매칭
- 폐선(타임머신) 기록: 3섹 전환 구간은 noriori에서 같은 edge이므로 자동 대응 (사업자 전환 승계 설정을 따름)
- 호환판의 끝은 승하차가 아니라 통과로 들어오고, 일괄로 승하차로 바꿀 수 있음 (§2.8 M). 전체판은 열의 값을 그대로 씀
- 이설 구간은 현행 행 = 새 선로, 타임머신 행 = 옛 선로로 처리. 실제 CSV 샘플로 구분 가능한지 확인 필요
- 승차km는 검증용: 매칭한 경로의 km와 다르면 확인 화면에 표시
- 역명 매칭 실패·모호한 행은 확인 화면에서 수동 선택. **행을 버리지 않습니다.** 끝내 못 맞춘 행은 원문을 보존하고 `unknown_ref`로 둠
- 별칭 표는 CSV 변환에 필요한 만큼 둠

**구현 현황 (2026-11-02)**: 일반판과 코멘트판 가져오기가 동작합니다. 설정 > 백업과 복원 > 노리츠부시 기록 가져오기에서 파일을 고르면 확인 화면을 거쳐 저장합니다.

- 판단은 core `importing/`에 있습니다. `CsvMatcher`가 행을 (계통, 역, 경로)로 맞추고 `planImport`가 새 기록, 있던 기록, 지운 기록을 가릅니다. 저장은 `Change` 하나라 한 번에 되돌립니다.
- 별칭 표는 따로 두지 않고 `names.sqlite`의 `name`과 `alias`를 씁니다. 괄호까지 맞는 계통을 먼저 찾고, 없으면 노선 이름으로 내려갑니다. 위 설계의 `names/aliases-noritsubushi.yaml`은 만들지 않았습니다.
- 순환 방향과 이설 선로는 파일의 km로 고릅니다. 순환 계통은 방향을 주지 않으면 짧은 쪽이 되므로, km가 있는 행은 두 방향을 모두 펼쳐 가까운 쪽을 저장합니다. 경로 때문에 사용자에게 묻지 않습니다.
- 못 맞춘 행은 `unknown_ref` 기록으로 남고 원문이 `import_raw`에 있습니다. 모양이 깨진 행은 확인 화면에만 나오고 저장하지 않습니다. 삭제했던 기록은 사용자가 고를 때만 되살립니다.
- 아직 없는 것: 수동 선택 화면, 중복 후보 표시, 일괄로 승하차로 바꾸기, 숨은 노드 `[枇杷島分岐点]` 표기의 시험. 표본에 없는 경우입니다.
- CP932는 `tools/gen_cp932.py`가 파이썬 코덱에서 만든 표로 읽습니다. `charset` 2.0.1은 9,604자 중 2,642자를 읽지 못했습니다.

### 10.3 내보내기 설계
앞 7열은 노리츠부시와 같게 두고, 뒤에 우리 열을 덧붙입니다. 열 이름이나 앞 7열만 읽는 도구는 그대로 동작합니다.

| 형식 | 인코딩 | 열 | 용도 |
|---|---|---|---|
| **호환판** | CP932, LF | `会社名,路線名,乗車開始駅,乗車終了駅,乗車キロ,乗車日` + 선택 `コメント` | 노리츠부시와 같은 모양 |
| **전체판** | UTF-8 (BOM), LF | 위 7열 + `ride_id,leg_seq,type,line_id,route_id,from_node,to_node,date_input,resolve_as_of,direction,from_alighted,to_alighted,transfer_nodes,service_id,node_id,created_at,dataset_version` | 탑승·방문의 경로 복원, 스프레드시트 |
| **JSON 백업** | UTF-8 | 머리말(형식, 스키마 버전, 판, 앱 빌드, 내보낸 시각)과 원본 테이블 전부 | **완전 복원**. 복원은 병합이라 새 기록이 사라지지 않음 |

| 항목 | 규칙 |
|---|---|
| 이름 | 일본어 공식명. 호환판은 그 노선의 현재 이름을 쓰고, 가져오기는 그 노선의 모든 기간 이름을 받음. 노리츠부시 방식의 괄호 노선명은 별칭 표로 역변환, 없으면 공식명. 숨은 노드가 경계이면 `export_name` |
| 한 행의 단위 | 호환판은 (사업자, 노선, 계통)마다 한 행. 전체판은 leg마다 한 행이고 같은 탑승은 `ride_id`를 공유 |
| 날짜 | `YYYY-MM-DD`. 미상은 `0000-00-00`. 연도만 아는 날짜는 호환판에서 `0000-00-00`으로 쓰고, 코멘트판이면 코멘트 끝에 원래 값을 덧붙임. 전체판은 `date_input`에 그대로 |
| 역 방문 | 호환판에는 넣지 않음. 전체판은 `type=visit` 행 |
| 한글 코멘트 | CP932에 한글이 없음. 못 적는 글자가 있으면 저장 전에 알리고 UTF-8로 저장 |
| 이스케이프 | RFC 4180 |
| 복원 보장 | JSON 백업은 모든 값을 그대로 복원 (CI 시험). 전체판 CSV는 탑승·방문의 경로와 날짜를 복원 (CI 시험). 사진, 여정, 시각, 열차명, 메모 외 값은 JSON으로 |

열 이름이 다른 CSV는 가져오기 화면에서 열을 직접 지정합니다.

## 11. UI 방향

**설정 화면 구성**: 위에서 아래로 데이터 판, 언어(한국어·영어·일본어 슬라이드 선택), 테마(라이트·다크·시스템 슬라이드 선택), 표시 설정(폐역·폐선, 열람 전용, 분기선), 백업과 복원, 데이터 출처, 오픈소스 라이선스, 앱 버전. 항목이 §3.2, §7, §8에 흩어져 있던 것을 여기에 모았습니다.

**표와 숫자**: 숫자 열은 고정폭 숫자로 맞춥니다. 진행 목록은 행을 얇게 해서 8분류가 한 화면에 들어오게 합니다. 위치 띠 양 끝에는 역 이름을 적습니다. 지도 칩은 `폐선`, `승차만`, `역 이름`입니다. 도도부현 타일을 누르면 이름을 보여 줍니다. 세로선 양옆으로 수치와 역 이름을 나누는 표 구조는 환승 앱에서 배웠고 위키식 줄 배치(§8.1)에 흡수했습니다.

経県値처럼 지도가 홈, 탭 → 하단 시트, 위에 큰 점수 하나. 지도 아래 `이어서 타기` 시트는 끌어 올리면 기록 탭처럼 노선 목록이 됩니다 (사용자 지시, 2026-11-02). 채도 낮은 배경 위에 탑승 상태 색만 또렷하게. 테마는 라이트·다크·시스템 설정 (§7.1). 하단 탭: **지도 · 기록 · 통계 · 설정**. 지도 홈 아래에 `이어서 타기` 시트가 있고 기록 추가는 그 시트의 버튼과 기록 탭의 (+)입니다. 선택 표시는 먹색이고, Material 기본 색(시드에서 나온 라벤더)은 쓰지 않습니다. 터치 영역 48dp 이상, 애니메이션 150–250ms. 화면별 목업은 하나씩 확인받으며 다듬음.

## 14. 데이터 모델 (컴파일 결과)

모든 기간 컬럼은 EDTF 원문 + lo/hi 범위입니다 (`valid_from·to`로 표기). `ongoing`은 최댓값입니다.

### 14.1 master.sqlite (읽기 전용)
**v1에서 뺀 것 (2026-11-01 실측)**: 아래 표 중 `lineage_stage`, `service_stop`, `route_edge`·`edge_km`·`node_position`·`hub_member`·`coverage`의 기간, `denominator`의 기간과 승계 끔 현행·연도 행은 없습니다. 앱은 `edge_life`·`edge_attr`로 날짜를 판정하고 `denominator_unit`을 합산합니다. 필요해지면 스키마 판을 올려 넣습니다. 표에 없지만 있는 것: `edge_pref`(도도부현별 km), `edge_shape`(탑승 오버레이용 encoded polyline), `denominator_unit.edge_id`·`certainty`, `service.valid_from·to`, `node_position.source`.

| 테이블 | 주요 컬럼 |
|---|---|
| `node` | id, kind(station/signal/junction/freight/pref_boundary), group_id, pref, export_name?(호환판 CSV 전용, §2.4) |
| `station_group` | id — 같은 역 묶음 (§2.8 B) |
| `hub` / `hub_member` | id / hub_id, node_id, valid_from·to, source, verified — 걸어서 갈아탈 수 있는 역 묶음 (§2.9) |
| `junction` (빌드 검사 전용, 배포 제외) | id, line_id, other_line_id, other_route_id?, node_id?, edge_id?, side?(up/down), continue, valid_from·to, source, verified (§2.9) |
| `lineage_stage` | 파생: lineage_id, seq, line_id, from_node, to_node, valid_from·to (§2.9) |
| `archive_stop` | id, line_id, route_id, after_id, before_id?, opened, closed, km?, source — 열람 전용 역 (§4.5) |
| `archive_line` | id, line_id, at_node, opened, closed, source — 열람 전용 노선 (§4.5) |
| `node_position` | node_id, lat, lon, quality(precise/approx/none), checked, valid_from·to — **지도 전용**. 역 이전(`move`)에 대비해 날짜가 있음 |
| `node_move` | old_node, new_node, moved_on — 역 이전. 재해석이 옛 노드 기록의 순서를 맞출 때 씀 (ARCHITECTURE §3.5) |

## 15. 기술 스택

Flutter · MapLibre(`maplibre_gl`) + PMTiles · OpenFreeMap 배경지도 · drift(SQLite, FTS5) · Riverpod · slang · Python 파이프라인(표준 라이브러리, tippecanoe) · GitHub Actions(APK, 서명 안 된 IPA, 데이터셋) · (나중에) 서버는 Docker 단일 컨테이너.

**라이선스**: 코드 Apache-2.0, 데이터 CC BY-SA 4.0. 위키백과, station_database와 같은 라이선스입니다. 선형은 재허락하지 않고 N02 원 조건을 따르며(2020년 이후 판 CC BY 4.0, 그 이전 판 商用可), `data/source/geometry/`에 조건을 적었습니다. OSM 유래 폐선 선형은 ODbL 별도 파일입니다. 사실 정보 자체에는 권리를 주장하지 않습니다 ([data/NOTICE.md](../data/NOTICE.md)). 앱의 설정에 데이터 출처 화면을 둡니다.

| 3분의 1 기둥, 중앙 기둥 | 줄기를 화면 안쪽에 두고 좌우로 가지 | 위키식 줄 배치가 높이가 낮고 이름이 덜 끊김 |
| 십자, 왼쪽 부채, 탭하면 펼침 | 역에 모이는 노선 수별 표현 | 캡슐과 곡선으로 통일. 펼침과 노선 이동이 충돌 |
| 같은 사업자만 표시 | 타 회사는 역 정보 시트로 | 위키처럼 전부 표시하기로 함 |
| 분기 방식 A·B·C | 노드 수평 / 노드 방향대로 / 실제 위치 | `side` 데이터로 위아래 줄을 정하고 선로 중간 분기만 예외로 둠 |
| 다음 역 + 사라지는 점선, `세키쇼선 · 신토쿠 방면` | 가지 끝 표현 | `다음 역 › 끝 역` 줄로 대체 |
| 끝 역의 가로·세로 화살표, T자 | 종착역 연결 | 줄기 끝 점선과 노선 이름으로 대체 |
| 양방향 노선 T자 끝, 두 갈래, 십자+부채 | 신칸센처럼 양쪽으로 이어지는 노선 | 캡슐과 세로선으로 대체 |
| 병주선 평행 표시 | 나란한 흐린 선 | 위키식에 자리가 없어 보류 (§8.1) |
| `transfers` 모듈 | 노선 쌍마다 환승 기록 | hub + junction으로 대체 |
| `reclassify` 이벤트 | 역 ↔ 신호장 전환 | `close_stop`으로 충분 |
| `variant`(옛/새) | 경로 고정 | 상대값이라 이설이 더 생기면 뜻이 바뀜. `resolve_as_of`로 대체 |

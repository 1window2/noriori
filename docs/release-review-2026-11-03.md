## 남은 것

- **ID 고정**: `data/ids.lock`, `id_redirect` 읽기. 1번 결정 뒤에 합니다.
- **공개 주소가 필요한 것**: 앱 안 데이터 내려받기, manifest 서명, 제보 링크, CI 첫 실행.
- **혼자 할 수 있는 P1**: CSV 확인 화면 5종, 즐겨찾기, 도도부현별 찾기, 기록 정렬·필터, 반복 탑승 횟수, 개인 기록 4종, 지도 환승 캡슐층, 검색 공백(`新京成` 등 애칭), 도도부현 경계 km 선형 계산.
- **지도 글자**: 글리프가 Noto Sans CJK TC라 일본 한자 일부가 번체 자형일 수 있습니다. JP로 다시 만들어야 합니다.
- **이름**: 계통 16개의 ko·en 이름, 열람 전용 579개의 en 이름.
- **기기 측정**: 저장→지도 100ms, 통계 200ms 같은 예산은 중급 Android에서 재지 않았습니다. 에뮬레이터 콜드 스타트는 0.84~0.98초입니다.
- **문서**: 명세 모순 32건 중 사용자 판단이 필요 없는 것은 문서만 고치면 됩니다. 목록은 추적표의 `문서 오류` 행입니다.

## 고치지 않은 작은 것

- 삭제한 방문과 여정을 5초 뒤 되살릴 화면이 없습니다.
- 범위 날짜가 `이번 달 km`에 잡힐 수 있습니다.
- 이설을 변경 소식이 폐지와 개업 두 건으로 알립니다.
- 긴 목록(`stats_screen`의 노선 표)이 지연 구성이 아닙니다. 최대 766행입니다.
- `rail.pmtiles` 최대 줌을 12로 낮추면 5.9MB 줄지만 화면 품질을 보지 않아 그대로 뒀습니다.

## ID 교체 뒤 재검토 (2026-11-03)

옛 판과 새 판을 표 단위로 대조했고, 코드의 ID 의존은 독립 검토로 따로 봤습니다.

| 항목 | 결과 |
|---|---|
| 참조 무결성 | 끊긴 참조 0, 중복 0. 앱 팩과 빌드의 ID 일치 |
| 값 | ID 말고 달라진 값 없음. 환승 묶음 한 행과 junction 출처 표기만 다름 (route_link 영향 0) |
| 재현성 | 처음부터 다시 빌드해도 해시 동일 |
| 역 시트 | 대표 역 하나의 노선만 보이던 문제를 고쳐 묶음 전체 노선을 노선 표 순서로 보임 |
| 묶음 대표 | ID 순 대신 환승역, 사업자 표 순서로 고름 |
| 완주 목록 | 같은 비율이면 ID 순 대신 표 순서 |
| 새 ID | 표에 없는 ID가 나오면 생성이 멈춤 |
| 순서만 바뀐 곳 | 환승 행 350곳, 역별 노선 124곳, 검색 동률. 내용은 같음 |
| 여정 찾기 | 400쌍 중 거리·환승이 다른 결과 0, 동률 경로 선택만 59쌍 |
| 옛 ID 기록 | 새 판에서는 확인 필요로 남음. 공개 전이라 CSV로 옮김 |

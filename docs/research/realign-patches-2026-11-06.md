- 격리 복사본 결과: 吾妻線 岩島 30.5, 川原湯温泉(구) 36.4 (1946-04-20~2014-10-01), 川原湯温泉 37.0 (2014-10-01~). 仙石線 東名(구) 1931-12-01~2015-05-30, 野蒜(구) 1928-04-10~2015-05-30, 새 역은 2015-05-30~. 石巻線 女川 2015-03-21~, 女川(구) 44.9 (1939-10-07~2015-03-21). 2010년 탑승 浦宿→女川(구) 2.5, 岩島→川原湯温泉(구) 5.9, 陸前大塚→野蒜(구) 3.2. `edge_link`(relocate)도 moved 행으로 옛→새 edge가 그대로 이어짐.

### 2단계로 미룬 이유 (보정 행만으로는 안전하지 않음)
1. **`tools/remap_edges.py` 키 충돌.** 기존 edge 번호를 가리키는 행은 `edge_keys.json`에 「노선|앞 노드|뒤 노드」 키가 있어야 하는데, 생성 원본에서 옛 선로 edge와 새 선로 edge가 양 끝이 같아(`l_agatsuma_line|n_iwashima|n_kawarayu_onsen`이 `e_001492`·`e_001499` 둘) remap이 「키가 없거나 여럿인 edge」로 멈춥니다. 키 표에 없으면 「키 표에 없는 edge」로 멈춥니다. 제안(격리 복사본에서 통과 확인):
   ```python
   # remap_edges.py: new 키에 옛 선로 표시를 붙인다. 지금 키 125개는 모두 alt 없는 edge라 그대로 맞음
   t_='@'+e['alt'] if e.get('alt') else ''
   new.setdefault('|'.join((e['seed_line'],e['a'],e['b']))+t_,[]).append(e['id'])
   new.setdefault('|'.join((e['seed_line'],e['b'],e['a']))+t_,[]).append(e['id'])
   ```
   그리고 `edge_keys.json`에 6행: `"e_001499": "l_agatsuma_line|n_iwashima|n_kawarayu_onsen@old"`, `"e_001500": "l_agatsuma_line|n_kawarayu_onsen|n_naganohara_kusatsuguchi@old"`, `"e_001598": "l_senseki_line|n_rikuzen_otsuka|n_tona@old"`, `"e_001599": "l_senseki_line|n_tona|n_nobiru@old"`, `"e_001600": "l_senseki_line|n_nobiru|n_rikuzen_ono@old"`, `"e_001614": "l_ishinomaki_line|n_urashuku|n_onagawa@old"`. 준비한 행의 번호는 지금 overrides 번호(HEAD)이므로 **다음 보통 `all.sh`의 remap 전에** 저장소에 넣어야 함께 옮겨집니다.
2. **女川은 원본 사건 범위가 깨짐.** 옛 선로 끝이 `n_onagawa`에서 `n_onagawa_old`로 바뀌어 원본의 `n_urashuku..n_onagawa@old` 사건 4개(개업 1939, 이관 1987, 불통 2011, 폐지 2015)가 풀리지 않고 컴파일이 멈춥니다. `events_fix.json`에 4행(`match` {type, route r_ishinomaki_line, edges [범위]} → `set` {edges: ["e_001614"]})이 필요합니다. 범위를 `n_onagawa_old`로 바꾸면 생성 단계 컴파일(보정 행 없음)에서 깨지므로 edge 번호로 고정합니다(`companion.json`).
3. **appsim FAIL 7개가 새로 생김** (all.sh가 멈춤). 대부분 같은 이름 한 노드를 전제로 쓴 시나리오이고, 노드를 나눈 기존 사례(常磐線)에도 이미 있는 앱 모델 한계입니다:
   - D1b 吾妻線 渋川→大前 날짜 모름 `partial 43.8` 기대 → `needs_input [55.3, 55.6]`. 常磐線 相馬→亘理도 기준 복사본에서 이미 `needs_input`(공통 구간 계산이 정차 노드가 다르면 안 됨).
   - D1c 吾妻線 2010 `km_on_date` 42.3 기대 → None. `km_axis`가 이웃 정차역을 차례로만 이음(常磐線 2010 浜吉田도 기준에서 None).
   - L2b 표본이 川原湯温泉(구)로 바뀌어 실패. 옛 선로에만 있는 옛 역 끝은 날짜 모름 탑승의 유효일이 「만든 날」이 됨. 常磐線 山下(구)도 기준 복사본에서 같은 값(2026-11-02)이라 기존 한계.
   - D3·S14 石巻線 시나리오가 2010·2013년 도착역을 `n_onagawa`로 고정. `n_onagawa_old`로 바꿔야 함.
   - S1·S2 끝 역이 옮긴 경우(女川 2.3 → 女川(구) 2.5): 사슬 검사의 세 칸 창이 마지막 역 뒤를 보지 못함. 탑승 펼치기(`expand`)는 정상(浦宿→女川(구) 2.5).
4. **`moved.json`에 보정 행 전용 노드를 넣으면 생성 단계·새 ID 모드 컴파일이 `nodes[old]` KeyError로 멈춤.** `tools/compile.py` moved 반복 맨 앞에 `if old not in nodes or new not in nodes:continue` 가드가 필요합니다(격리 복사본에서 확인). `gen_source.py`·`gen_geometry.py`는 이미 없는 노드를 건너뜀.
